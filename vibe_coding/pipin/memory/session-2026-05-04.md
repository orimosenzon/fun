# סשן 2026-05-04

## נושא הסשן
יישום Location Canon — המעבר מ-single-player ל-shared world.

## ההחלטות שהתקבלו
- **גרסה A — Location Canon:** הראשון שמגיע למקום יוצר אותו לכולם (לא גרסה B).

## מה נבנה

### server.py
- הוספת SQLite (`pipin_world.db`)
- `GET /api/world/location/<id>` — מחזיר canon narrative + image אם קיים, 404 אם לא
- `POST /api/world/location/<id>` — שומר location (רק אם לא קיים עדיין — idempotent)
- `init_db()` נקרא בהפעלת השרת

### js/api.js
- `getPlayerId()` — UUID בחינם מ-localStorage, נשמר לצמיתות
- `fetchCanonLocation(locationId)` — שואל שרת, fallback שקט אם אינו זמין
- `saveCanonLocation(locationId, narrative, imageData)` — שומר לשרת, שקט בשגיאה
- `generateLocationImage` — בודק שרת לפני שמפעיל Imagen. אם יש canon image משתמש בו.

### js/game.js
- `handleFirstVisit(locationId, freshNarrative)` — async:
  - אם canon קיים: מציג `📜 [הנרטיב של המבקר הראשון]`
  - אם לא: שומר את הנרטיב הנוכחי כ-canon
- `applyResponse` הפכה ל-async, מחכה ל-`handleFirstVisit`

## שיחה עם ג'מני — מה רלוונטי
- **Pollinations.ai** — יצירת תמונות בחינם ללא API key, רק URL. שווה לבחון כתחליף ל-Imagen.
- LangChain.js / Supabase — נכונים לשלב הבא, לא עכשיו.

## הצעדים הבאים
1. **Pollinations.ai** — להחליף Imagen ב-Pollinations (מסיר חסם billing לתמונות)
2. **Player identity UI** — להציג לשחקן כמה מקומות הוא בנה בעולם
3. **Deploy** — כדי שה-shared world יהיה באמת משותף צריך שרת ציבורי (Render / Railway)
