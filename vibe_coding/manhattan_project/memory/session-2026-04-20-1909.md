### 1. באג בחישוב HUD
המשתמש שם לב ש-"Added $33B − Lost $30B" לא מסתכם ל-Net שמוצג. הסיבה: `saturation haircut` נספר פעמיים — הוא כבר הורד מ-`conAdj` (הערך ה-"Added") וגם נכלל ב-`totalLost`.

**תיקון** (בלוק `updateStats` סביב שורה 1032):
- הוספתי `hudLostSum = premLost + tourLost + envLost` (בלי satLoss)
- HUD מציג: Added = conAdj, Lost = hudLostSum, Net = Added − Lost
- שורת הסטורציה נשארה ב-Value Breakdown (הפירוק המלא שקוף)

### 2. סליידרים למקרו-פרמטרים
הוספתי כרטיסייה חדשה "Model Parameters — Macro":
- Supply elasticity (0.5–3.0, דיפולט 1.5) — הכי רגיש
- Luxury stock (30–150M sqft, דיפולט 60M)
- Tourism value ($0–600B, דיפולט $320B)
- Env. & health ($0–400B, דיפולט $100B)
- כפתור "↺ Reset to defaults" שמחזיר את כל 8 הסליידרים לברירות מחדל

פונקציה `resetParams()` + עדכון `onSliderChange()` לקרוא את הפרמטרים ולעדכן את `MACRO`.

### 3. באג קריטי: CALIB נרמל החוצה את השינויים
המשתמש ראה שהזזת הסליידרים של premium/lambda לא שינתה את Existing value lost. הסיבה: `CALIB = 500e9 / totalBaselineScore` היה מחושב מחדש בכל `recomputeBaseline()`. לכן כשה-user הוריד את premiumMax ל-10%, ה-score ירד אבל CALIB עלה לפצות, וה-total premium loss נשאר זהה.

**תיקון:** CALIB עבר מ-`let` ל-`const` (כיול חד-פעמי מ-Barclays $500B על בסיס הדיפולטים). `recomputeBaseline()` עדיין מעדכן את `totalBaselineScore` (נכון), אבל לא נוגע ב-CALIB.

## שיחה על אמינות המודל
המשתמש שאל "האם אפשר להתייחס לתוצאה ברצינות?". התשובה שניתנה:
- **כיוונית כן:** הסימן השלילי + סדרי גודל של מאות מיליארדים מגובים במחקרים (Nicholls & Crompton, Barclays 2018). דירוג Edge < South < All גם משקף hedonic decay נכון.
- **מספרית לא:** saturation haircut של $917B הוא אקסטרפולציה פרועה מ-Saiz (2010, שמדד elasticity לשינויים שוליים). חלק מהכיול מעגלי (מכוייל כדי לשחזר $500B). אין general equilibrium / אפקטים התנהגותיים / דינמיקה לאורך זמן.

המודל הוא **כלי חשיבה**, לא **כלי תחזית**. הסליידרים עכשיו מאפשרים למשתמש להרגיש את הרגישות הזו — זה השיפור החשוב ביותר היום.
