# סשן 2026-09-17 (סשן ראשון, פתיחת הפרויקט)

## מה נעשה
- נפתח הפרויקט: משחק 2048 בדפדפן + למידת חיזוק (DQN, Actor-Critic) ב-PyTorch על ה-GTX 1060.
- **סביבה**: `.venv` עם `torch==2.10.0+cu126`. ה-PyTorch הגלובלי (cu128) לא תומך ב-1060 (sm_61).
- **המשחק** (`game/`): שחזור נאמן של המקור (Grid/Tile/GameManager/HTMLActuator/Input/Storage, CSS ואנימציות,
  מובייל). נבדק ב-Playwright: 400 מהלכים מול מנוע הפייתון בלי סטיות, ניצחון/סיום/Keep going/localStorage.
- **פאנל AI במשחק** (`game/js/agent.js` + `game/weights/dqn.js`): הסוכן המאומן משחק בתוך הממשק, פסים עם
  ערכי Q לכל כיוון. הרשת ב-JS טהור, נבדקה מול PyTorch (argmax זהה 100%, הפרש 0.0005).
- **מנוע מהיר** (`rl/game2048.py`): טבלאות חיפוש על שורות 16 סיביות, ~450K מהלכים/שנייה. בדיקות ב-`rl/test_game2048.py`.
- **DQN** (`rl/dqn.py`): Double DQN, replay 500K, עדכון רך, epsilon 1→0.02 ברבע הראשון, מסכת מהלכים, n-step אופציונלי.
  ניסוי הסרה: n-step=3 גרוע בבירור מ-1-step (1,847 מול 3,844 ניקוד אימון ב-2.5M). לוגים ב-`logs/ablation_*`.
- **A2C** (`rl/actor_critic.py`): 64 סביבות × 16 צעדים, GAE 0.95, אנטרופיה 0.01, נרמול יתרונות. פיילוט 4 דקות:
  ניקוד אימון 7,700 ו-21% הגעה ל-1024, הרבה מהר יותר מ-DQN.
- **הערכה ודו"חות**: `rl/evaluate.py` (1,000 משחקים + קווי בסיס אקראי/חמדן + הקלטות + העדפת כיוונים + שיעור
  "אריח גדול בפינה"), `rl/make_reports.py` (Chart.js, RTL, מצב כהה, תצוגת טבלה לכל גרף, שחזור משחקים).
  תבנית הדו"ח נבדקה על נתוני ביניים ונראית טוב. הניתוח המילולי נטען מ-`reports/data/analysis_<name>.html` (עוד לא נכתב).
- **תיקון חשוב**: `play_games` אסף את המשחקים הראשונים שמסתיימים מ-N סביבות, וזה מוטה לטובת משחקים קצרים
  (4,060 מול 4,904 לאותה רשת). תוקן: כל סביבה תורמת רק את המשחק הראשון שלה. ריצת ה-DQN הופעלה מחדש אחרי התיקון.
- **README.md** מלא בעברית כולל מילון מונחים עם אטימולוגיה. כרטיס נוסף לדף הפרויקטים (`projects_page/projects.json`).

## מצב נוכחי
- **ריצת ה-DQN המלאה רצה ברקע בזמן סגירת הסשן** (התחילה 17:50, 20M מעברים, ~4,600 מעברים/שנייה, צפויה להסתיים
  בערך ב-19:05). פלט: `logs/dqn_stdout.log` (השורה `done.` מסמנת סיום), `logs/dqn_train.jsonl`,
  `checkpoints/dqn_{best,last,final}.pt`. בסגירה: 5.8M מעברים, הערכה חמדנית 4,353.
  אם צריך לעצור: `pkill -f "rl/dqn.py --run-name dqn"`.
- `game/weights/dqn.js` הוא ייצוא ביניים (נקודת ביקורת ~5M מעברים); לייצא מחדש בסוף האימון.
- A2C עדיין לא רץ במלואו. הדו"חות עדיין לא נוצרו (הקבצים הישנים מנתוני הביניים נמחקו; הקישורים ב-README
  ובמשחק יעבדו אחרי `make_reports.py`).

## צעדים הבאים
1. לוודא ש-DQN הסתיים (`grep done logs/dqn_stdout.log`), ואז להריץ A2C באותו תקציב זמן:
   `./.venv/bin/python rl/actor_critic.py --run-name a2c --time-limit-min <דקות ה-DQN> --log-every 500000 --eval-every 5000000`
   (ריצה אחת בכל פעם: RAM צפוף, ~1.3GB לתהליך).
2. `./.venv/bin/python rl/evaluate.py --all` ואז `./.venv/bin/python rl/make_reports.py`; לצלם את שלושת הדו"חות
   (סקריפט `shot_report.py` מהסקראצ'פד עשה זאת עם Playwright) ולבדוק בעין.
3. לכתוב את הניתוח המילולי: `reports/data/analysis_dqn.html`, `analysis_ac.html`, `analysis_comparison.html`
   (קטעי HTML בעברית), ולהריץ שוב `make_reports.py`.
4. לייצא משקולות סופיות לשני הסוכנים (`rl/export_weights.py`) ולבדוק את פאנל ה-AI במשחק עם שניהם.
5. לעדכן את כרטיס הפרויקט: להסיר את תג "אימון בתהליך", להוסיף קישור ל-`2048/reports/comparison.html`, ולבנות
   מחדש עם `python3 projects_page/build.py`.
6. אופציונלי: ריצת DQN שנייה עם שיפור אחד (למשל דעיכת epsilon מהירה יותר) כנקודת השוואה נוספת.
