# סשן 2026-06-01 05:31 — בנר שגיאות מובנה + פלטת צבעים קבועה

## מה נעשה

**שינוי 1 — `humanize_error()` ב-`app.py`:**
- פונקציה אחת שמזהה דפוסי שגיאה ומחזירה `{message, details, link_url, link_text, technical}` לרינדור ב-UI.
- מטפלת ב-7 קטגוריות: Gemini quota (חולץ את `quotaValue` מהמטענה), Gemini bad-key (401/403), Gemini server (5xx), Anthropic rate-limit, Anthropic auth, Anthropic timeout/network, JSON parse, ו-fallback כללי.
- שלושת אתרי ה-`try/except` (`run_job`, `evaluate_endpoint`, `run_evaluate_job`) הוחלפו ל-`except Exception` יחיד + `log.exception(...)` לתיעוד ב-`haskala.log`, ואז `humanize_error(e, action=...)`.
- ב-`evaluate_endpoint` הסינכרוני: השדה `error` נשאר מסיבת backward-compat (קוראים קיימים שמסתכלים רק על `.error`), אבל גם השדות הנוספים נשלחים.

**שינוי 2 — בנר שגיאות מובנה ב-`templates/index.html`:**
- אלמנט חדש `#error-banner` עם כותרת (`⚠️ + message`), פסקת `details`, לינק פעולה (`error-link`), ובלוק מתקפל `<details>` עם `<pre>` ל"פרטים טכניים" (raw exception, LTR, monospace).
- פונקציה גלובלית `window.haskalaRenderError(err, fallback)` שמרינדרת את הבנר ומסתירה את progress-box. נקראת משני ה-IIFE (OCR + הערכה) דרך `progressError`/`evalProgressError`.
- `window.haskalaClearError()` למסכי טעינה.
- כל ה-`alert(data.error || ...)` הוחלפו לבנר.
- אומת בעצמו: smoke test על 5 סוגי שגיאות עבר; אבישי אישר חזותית את הבנר על quota אמיתי.

**שינוי 3 — פלטת צבעים קבועה לקריטריונים ב-`app.py`:**
- בעיה שהתגלתה: ב-rubric של משרד החינוך, גם MECHANICS וגם LANGUAGE USE יצאו סגולים — MECHANICS תפס keyword "mechanics" → סגול, ו-LANGUAGE USE לא תפס keyword בכלל ונפל ל-md5 fallback שגם הוא הכיל סגול. קוליז'ן.
- פתרון: הוחלף ה-keyword matching ב-`_PALETTE` של 11 צבעים מובחנים, מתוכם סלוטים 0-3 מקובעים לקריטריונים של הרובריקה הדיפולטית (משרד החינוך) בסדר שכיחות יורד של סימונים inline:
  - 0 אדום `#d9534f` — MECHANICS
  - 1 כחול `#2c7be5` — LANGUAGE USE
  - 2 ירוק `#28a745` — VOCABULARY
  - 3 ענבר `#f0a000` — CONTENT AND ORGANIZATION
- סלוטים 4-10: סגול, כתום, טורקיז, מג'נטה, חום, נייבי, ליים — מחולקים דטרמיניסטית לקריטריונים חדשים לפי `md5(name) % 7` מתוך `_FALLBACK_RANGE = [4..10]`. כך שום קריטריון לא-מקובע לא יכול להתנגש בצבעי הקריטריונים המקובעים.
- `attach_colors()` שונה: כעת **דורש מחדש** את הצבע בכל קריאה (לא משמר ערכים קיימים). המשמעות: JSON שמור עם צבעים ישנים ייטען עם הפלטה החדשה — עקביות לאורך זמן.
- אומת: כל ארבעת הקריטריונים של משרד החינוך פוגעים בסלוטים 0-3. ESL rubric: 3 מתוך 4 פוגעים בסלוטים המקובעים, "Task Achievement & Coherence" נופל ל-10 (ליים).

## החלטות

- **לא להשתמש ב-LLM לתרגום שגיאות** — קומפילציה ידנית של דפוסים יותר אמינה (גם אם ה-API נפל, התרגום יעבוד), דטרמיניסטית, וחינמית.
- **`humanize_error` שמרני בהזרקת מידע אישי** — `technical` חתוך ל-2000 תווים. מספיק לדיבאג, לא מציף.
- **פלטה של 11 צבעים, לא טבלת lookup מלאה** — קריטריונים חדשים (מרובריקה עתידית) ייפלו דטרמיניסטית. אם יבוא קוליז'ן בעתיד בין 2 קריטריונים בלתי-מקובעים בתוך אותה רובריקה, אפשר להוסיף tuple ל-`_PINNED_CRITERION_RULES`.
- **`attach_colors` overrides** — שיקול: עקביות > backward-compat לקבצים שמורים. הסיכון נמוך (אין UI לקביעת צבעים ידנית).

## מה התגלה — מכסת Gemini Free Tier
