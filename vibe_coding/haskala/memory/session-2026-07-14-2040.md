`haskala-ocr` ו-`haskala-math` נתקעו שניהם על "Preparing Space" / `RUNTIME_ERROR`
(`errorMessage: "Scheduling failure: unable to schedule"`) — תקלת קיבולת בצד HF
בשכבת cpu-basic החינמית, לא קשור לקוד. נפתר ע"י **Factory rebuild** (Settings → Factory
rebuild) בשני ה-Spaces. הוגדר טוקן HF fine-grained מקומי (`~/.cache/huggingface/token`,
scope: read all + write על שני ה-Spaces הספציפיים) — אפשר לבדוק runtime status דרכו
(`HfApi().space_info()`), אבל ל-**restart/factory-reboot** התגלה ש-HF דוחה 403 גם עם
write על repos ספציפיים — צריך טוקן קלאסי "Write" רחב יותר אם רוצים לעשות זאת
פרוגרמטית בעתיד; כרגע restart נעשה ידנית בדפדפן.

## scan2 — תעלומת ה-400 Bad Request נפתרה: זו הייתה בעיית קרדיט, לא קוד
דרך Cloud Run → scan2 → Observability → Logs (עם פילטר לפי "Bad Request") אותרה השגיאה
המלאה מ-Anthropic:
```
anthropic.BadRequestError: Error code: 400 - {'type':'error','error':{'type':'invalid_request_error',
'message':'Your credit balance is too low to access the Anthropic API...'}}
```
**זה לא היה קשור ל-`detect_rotation` או ל-`ORIENT_MODEL`** כפי שחשדנו בסשן הקודם — פשוט
נגמר יתרת הקרדיט בחשבון Anthropic שמפתח ה-API של scan2 מוגדר עליו. אורי טען קרדיט,
ואומת ריצה מוצלחת מקצה לקצה: `200 OK` על כל קריאות `/v1/messages`, orient detection
עבד, נוצר דוח `.docx` והועלה ל-Drive.

## באג חדש וחמור: `run_workspace_scan()` לא עושה בכלל dedup — כל טריגר מעבד הכול מחדש
מתוך `main.py` (מהגיבוי החלקי שנמצא, ראה למטה):
```python
for subm in subms:
    # check if we checked this submission          <- הערה בלבד, אף פעם לא מומש!
    ...
    checker.check_hw(drive_service, file_ids, folder_id)
```
**אין שום מנגנון מעקב** — כל הרצה של `process_my_drive_files` (בין אם מ-Cloud Scheduler
ובין אם מ-publish ידני ל-Pub/Sub topic `scanNow`) עוברת על **כל הקורסים → כל המטלות →
כל ההגשות** ומריצה מחדש בדיקת Claude (Opus!) על כל קובץ, בלי זיכרון של מה שכבר נבדק.

**תוצאה בפועל הערב: אורי שרף כ-20$ בטעות.** כשבדקנו מה קרה — ה-Cloud Scheduler היחיד
שקיים (`HourlyCheck`, `us-central1`, cron שעתי) נמצא כבר ב-state `paused` ומעולם לא
רץ ("Has not run yet") — כלומר **הוא לא היה מקור הדליפה**. המקור בפועל: **טריגר ה-
publish הידני ל-`scanNow`** שביקשתי מאורי לבצע פעמיים בסשן הזה כדי לבדוק את תיקון
הקרדיט — כל publish כזה, בהיעדר dedup, הריץ reprocessing מלא של כל ההגשות בקלאסרום
עם מודל Opus. לקח באחריות על כך שלא הערכתי את היקף הנזק לפני שהצעתי לבדוק כך.

**מצב נוכחי בטוח ללילה:** אין scheduler פעיל, ה-trigger היחיד שנותר הוא publish ידני
ל-topic. כל עוד אף אחד לא עושה זאת, שום דבר לא ירוץ מעצמו.
