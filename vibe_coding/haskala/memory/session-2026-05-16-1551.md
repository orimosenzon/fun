# סשן 2026-05-16 (15:51) — אריזה לבדיקת OCR + פריסה לענן

## מטרת הסשן
לפני המשך הפרויקט, לוודא שה-OCR מספיק טוב. הבדיקה תיעשה ע"י משתמש בודק חיצוני
על תרגילי תלמידים אמיתיים — לכן צריך כלי נוח, ופריסה שלא דורשת התקנה.

## החלטות ארכיטקטוניות
- **רוב מה שנדרש כבר היה קיים** — זו הייתה הפשטת UX + אריזה, לא בנייה מחדש.
- **דסקטופ נייטיב (pywebview)** עוטף את אותו Flask — דיאלוגי קובץ נייטיב שזוכרים
  תיקייה אחרונה. שימוש חוזר ב-100% מהקוד. Linux דורש Qt backend + qtpy.
- **progress bar אמיתי לפי שלבים** — `process_pdf` הוסב לגנרטור שמשדר התקדמות
  (render→deskew→ocr→segment→crop) דרך SSE. הקוד המת הישן נמחק (אין כפילות צנרת).
- **3 כפתורים** במסך אחד: פענח קובץ / העלה קובץ מפוענח / שמור קובץ מפוענח.
  מערכת ההערות הקיימת לא שונתה. נשמר fallback לדפדפן.
- **פריסת ענן = זרימת הדפדפן** (לא הדסקטופ). נבחר **Hugging Face Spaces** (חינמי,
  16GB RAM, secrets, SSE עובד). דחיית פתרונות בתשלום.
- **מפתח Anthropic** — הוחלט להשתמש בקיים. החשבון במודל קרדיטים מראש עם
  auto-reload כבוי → היתרה עצמה היא תקרה קשיחה (הגנה חזקה יותר מתקרה חודשית).
  קריטי: להשאיר auto-reload כבוי.

## אבטחה
- **באג שתוקן**: endpoints מבוססי-path (`/load?path=`, decode-by-path) — בטוחים
  מקומית, חור file-read בענן ציבורי. כעת מוחזר 403 אלא אם `HASKALA_DESKTOP=1`.
- **Basic Auth** דרך `before_request` — חוסם הכל כולל OCR כש-`HASKALA_USER`/
  `HASKALA_PASS` מוגדרים. בדסקטופ/מקומי מדולג. אזהרת לוג אם נפרס בלי קרדנציאלס.

## מצב סופי — פרוס ועובד
- Space: `https://orimosenzon-haskala-ocr.hf.space` (ריפו Space נפרד ב-HF).
- מאומת: build הצליח (RUNNING), נעילת path → 403, Basic Auth נאכף → 401 בלי
  קרדנציאלס. המשתמש אישר ויזואלית שהזרימה המלאה (פענוח + SSE דרך פרוקסי HF
  + תוצאה) עובדת מקצה לקצה.
- requirements פוצל: `requirements.txt` (ליבה/ענן) מול `requirements-desktop.txt`
  (pywebview/Qt). Dockerfile: gunicorn, worker יחיד (JOBS בזיכרון), SSE-friendly.
- index.html עודכן עם לינק לכלי (מסומן כמוגן בסיסמה).

## פתוח לסשן הבא
1. **הצעד שעוד לא נעשה** (מהסשן הקודם): connected-components לתיקון גליץ'
   רצועת-הרפאים בחיתוך השורות (16/17 → 17/17). תלוי בתוצאות בדיקת המשתמש החיצוני.
2. **לאסוף משוב מהבדיקה** — אם איכות ה-OCR מספקת, להתקדם; אם לא, לשפר לפני

3. בדיקה על PDF-ים מגוונים (איכויות/זוויות/כתבי-יד) — הכיול עדיין על דגימה אחת.
4. הכרעת נקודת כניסת התלמיד (Classroom / companion app) — עדיין פתוחה.
