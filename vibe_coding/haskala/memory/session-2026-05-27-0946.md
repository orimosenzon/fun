# סשן 2026-05-27 — תכנון אינטגרציה עם Google Classroom/Drive (החלטה: גישה B)

## החלטות שהתקבלו

### 1. ארכיטקטורה: אתר נפרד (לא אינטגרציה בתוך Classroom)
המשתמש שאל אם אפשר להטמיע כפתורים בתוך ממשק Classroom עצמו. נסקרה אפשרות
**Google Classroom Add-ons** הרשמית והוסקה ההחלטה שלא ללכת על זה כרגע:
- דורש **Google Workspace for Education Plus** — רוב בתי הספר בישראל לא משלמים על זה
- דורש פרסום ב-Marketplace + אישור גוגל (4-6 שבועות)
- Chrome Extension נדחה כי שביר (גוגל משנים את ה-DOM של Classroom).

**ההחלטה:** ממשיכים עם אתר Flask נפרד. אם הפרויקט תופס בעתיד — מעטפת Add-on
תוכל להיבנות מעל אותה לוגיקה.

### 2. גישת הזרמת ההגשות: אופציה B (Google Picker), לא Classroom API
המשתמש בחר להתחיל מ-**Google Picker** במקום Classroom API:
- המורה לוחץ כפתור באתר → נפתח Picker של גוגל (UI מוכר של Drive)
- בוחר תיקייה → מקבלים `folder_id` → Flask מוריד את התמונות → Claude Vision → דשבורד
- Scope יחיד: `drive.readonly` (פשוט יותר מ-Classroom שדורש 4-5 scopes)
- **חיסרון מוכר:** קישור קובץ↔תלמיד יידרש regex על שמות הקבצים (לא אמין כמו StudentSubmission ב-Classroom)
- **חיסרון מוכר:** אין החזרת ציון אוטומטית ל-Classroom — צריך export/copy-paste

### 3. הזרימה הטכנית של אופציה B (מאושרת)
```
1. המורה מתחבר ב-OAuth (פעם אחת לחיים) — scope: drive.readonly
2. לוחץ "בחר תיקייה" → google.picker.PickerBuilder() נפתח (gapi.js)
3. Picker מחזיר folder_id ל-JS שלנו
4. JS שולח ל-Flask: POST /process-folder {folder_id}
5. Flask: drive.files.list → לכל תמונה: get_media + Claude Vision
6. דשבורד עם SSE כמו שדנו לאופציה A (progress bar בזמן עיבוד)
```

## הסבר ההרשאות (מה שהמשתמש שאל)

הפרדה חשובה שהובהרה:

### רמה 1 — הגדרה אצל אורי (פעם אחת לחיים)
1. יצירת פרויקט ב-Google Cloud Console
2. Enable APIs: **Google Picker API** + **Google Drive API**
3. יצירת **שני credentials**:
   - OAuth 2.0 Client ID (web application) — מקבל `client_id` + `client_secret`
   - API Key (עם restriction ל-Picker API + HTTP referrer של הדומיין)
4. OAuth Consent Screen — External, scope אחד (`drive.readonly`),
   רשימת test users (עד 100 לפני verification)

### רמה 2 — אצל המורה
- **פעם אחת לחיים:** מסך OAuth consent של גוגל → Allow
- **כל שימוש:** רק לוחץ "בחר תיקייה" ובוחר. אין הרשאות חוזרות.

המשתמש שאל בלבול שניסחתי לא ברור — הובהר ש"Enable APIs לכל אחד" התייחס
לכל אחד מה-APIs, לא לכל מורה.

## verification של גוגל — לא בשלב MVP
- `drive.readonly` הוא **sensitive scope** → דורש brand verification + סרטון
  הדגמה + privacy policy + ToS (תהליך 4-6 שבועות)
- **לא צריך עכשיו** — Test users mode (עד 100) מספיק ל-POC
- ייצור משוב לפני verification: מורים יראו מסך "Google hasn't verified this
  app" — צריך ללחוץ Advanced → Go to Haskala (unsafe). מרתיע אבל לא חוסם.

## אופציות הרשאה שנשקלו ונדחו
- **`drive.file`** — non-sensitive, מסך OAuth ידידותי, אבל לא תופס את הילדים של תיקייה
  שנבחרה ב-Picker. לתיקייה עם 30 תמונות זה לא עובד בלי לבקש פיקר על כל קובץ.
- **`drive` (full)** — restricted scope, דורש CASA assessment יקר (אלפי דולרים).

**הבחירה:** `drive.readonly` — sensitive אבל סביר ל-POC, ובהמשך מתאים גם
לפרודקשן אם נעבור verification.
