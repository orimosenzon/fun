# Session 2026-06-03 14:39 — הוספת Groq (Llama 4 Scout) כספק חינמי לבורר המודלים

## סוג הסשן

## רקע
מתוך אסטרטגיית BYOK/fallback שגובשה בסשן הקודם — להוסיף ספק חינמי אמיתי שיכול לשמש כשגם Claude וגם Gemini נגמרים. Groq מציעים `meta-llama/llama-4-scout-17b-16e-instruct` ב-free tier (~30 RPM) עם vision support, כך שאותו ערך בורר משרת גם את ה-OCR (vision) וגם את ה-evaluation (טקסט).

## מה נעשה (בקוד)

### 1. תוספת ספק Groq ל-app.py
- ערך חדש בבורר: `groq-scout` → "Groq (Llama 4 Scout — חינמי)"
- `_GROQ_MODEL_IDS` + `_is_groq()` + `_groq_model_id()` + `_groq()` עצלן (לקוח רק כשבוחרים את הספק → Claude-only deployments לא נשברים)
- `_ocr_groq()` — שולח base64 data URL דרך chat.completions.create
- ענף Groq ב-`evaluate_with_rubric` ו-`evaluate_with_rubric_stream` (כולל streaming)
- Groq SDK תומך רק ב-`response_format={"type":"json_object"}` (לא json_schema) → הוספתי קבוע `_GROQ_EVAL_SHAPE_HINT` שמספח את הסכמה לטקסט של ה-user turn
- `groq>=0.11.0` ב-requirements.txt

### 2. טיפול שגיאות Groq ב-humanize_error
- RateLimitError → "חרגת ממכסת Groq" + לינק ל-console.groq.com/settings/limits
- AuthenticationError → "מפתח Groq API לא תקף"
- APIConnectionError/APITimeoutError → "החיבור ל-Groq נכשל"

### 3. תיקון שגיאת UX — KeyError על env vars
**הבעיה שעלתה בבדיקה הראשונה:** המשתמש לחץ "פענח קובץ" עם Groq בלי שה-Secret היה מוגדר בספייס. הקוד זרק `KeyError('GROQ_API_KEY')` כש-`_groq()` ניסה לקרוא ל-`os.environ["GROQ_API_KEY"]`. השגיאה נתפסה תחת הענף הגנרי `(json.JSONDecodeError, KeyError, ValueError)` שהציג הודעה מטעה: "המודל החזיר תשובה לא תקפה".

**הפתרון:** הוספת ענף ייעודי ב-`humanize_error` *לפני* הענף הגנרי שמזהה KeyError על אחד מהשמות הידועים (GROQ_API_KEY / ANTHROPIC_API_KEY / GEMINI_API_KEY) ומציג הודעה ברורה + לינק לקונסול של הספק.
