## מה נבדק ואומת (מקוד, ללא הרצה)
- `main.py` (מהגיבוי) משתמש ב-`@functions_framework.cloud_event` — כלומר טריגר
  Eventarc/Pub-Sub **push** ל-Cloud Run, לא הרצה חד-פעמית.
- אושר גם מסשן 2026-07-13 (אחה"צ): יש **Pub/Sub push subscription** בפועל על topic
  `scanNow`, עם `Cloud Scheduler Service Agent` בהרשאות — כלומר יש גם scheduler
  מחזורי (כרגע `HourlyCheck` ב-paused) בנוסף לפרסום ידני.
- **מסקנה:** `run_workspace_scan()` הוא loop סינכרוני על כל הקורסים/מטלות/הגשות עם
  קריאת Opus Vision לכל הגשה, בלי ack מוקדם. אם הריצה חורגת מ-ack deadline של
  ה-subscription או מ-timeout של Cloud Run — Pub/Sub **redeliver**-ת את ההודעה ומריצה
  סריקה מלאה מהתחלה, כי אין dedup. כך שני publish-ים ידניים יכלו להצטבר להרבה יותר
  משתי ריצות מלאות בפועל. עדיין **לא אומת מהלוגים בפועל** — זה next step.
- **תשובה לשאלה "אם לא נזרוק exception, זה ימנע קריאות חוזרות?"** — לא בהכרח: catch
  של exception מטפל רק בנתיב אחד (500 שמוחזר בגלל שגיאת קוד). נתיב הכישלון הסביר יותר
  כאן הוא **timeout** — התהליך נהרג באמצע לפני שהקוד בכלל מגיע לשלב שבו יכול לתפוס
  exception, אז אין דרך "לתפוס" את זה בצד הקוד בלבד. הגנה אמיתית: (1) ledger של
  submission IDs שכבר טופלו — הכי חשוב, הופך retry לזול; (2) `maxDeliveryAttempts`
  נמוך + dead-letter topic על ה-subscription; (3) ack מהיר + עבודה אסינכרונית בנפרד;
  (4) budget alert כגיבוי אחרון.

## החלטה: לשכפל scan2 לפרויקט עצמאי `oris-scanner`
סוכם עם אורי (3 שאלות, כל התשובות):
1. **scope:** אותו פרויקט GCP (`master-gecko-500709-t0`), Cloud Run service חדש +
   Pub/Sub topic חדש (לא פרויקט GCP נפרד).
2. **תוכן יום ראשון:** שכפול scan2 **+ החלפת ליבת המתמטיקה בבדיקת-שפה** (לא רק clone
   נקי) — כלומר oris-scanner ישמש גם לתיקון הבאג ארכיטקטונית וגם לתיקון הנושא (שפה
   במקום מתמטיקה), בהנחה שזה אכן הכיוון הנכון עבור הקורס של ירון.
3. **סדר:** קודם לבדוק לוגים אמיתיים (Cloud Run) כדי לאשר את תאוריית ה-retry
   בעובדות, **לפני** בניית oris-scanner.

- gcloud **מותקן מקומית** ב-`~/google-cloud-sdk/bin/gcloud` (למרות שלא ב-PATH),

  כלי חד-פעמית וחוסמת.
- **התבקש מאורי:** להריץ בעצמו `~/google-cloud-sdk/bin/gcloud auth login` בטרמינל
  שלו (לא דרך קלוד). מאותה מכונה/משתמש, כך שהטוקן ב-`~/.config/gcloud/` יהיה זמין גם
  לקלוד בהמשך. **טרם בוצע/אושר ע"י אורי עד סוף הסשן.**
