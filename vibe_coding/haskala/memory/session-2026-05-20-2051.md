# סשן 2026-05-20 — הערכת תרגיל לפי רובריקה + טיפול בפריסה ל-HF

## מה נעשה

### פיצ'ר חדש: הערכת תרגיל לפי רובריקה
משתמש (אבישי) ביקש להוסיף אפשרות להעריך תרגיל מתומלל לפי רובריקה. רובריקת ברירת מחדל: ESL לכיתה ט' לפי CEFR (מועתקת מ-PDF שצירף).

**Backend** (`app.py`):
- תיקיית `rubrics/` עם קובץ JSON אחד (`name` + `content` כטקסט חופשי).
- `GET /rubrics`, `GET /rubrics/<id>`, `POST /rubrics` — רשימה / תוכן / יצירה.
- `POST /evaluate` — שולח טקסט מתומלל + רובריקה ל-Claude/Gemini, מחזיר JSON עם `criteria[]` (שם, score, max_score, feedback) + `overall_score` + `overall_feedback`. Claude מחלץ את הקריטריונים מהרובריקה (לא קבוע בסכימה).
- `POST /evaluation/docx` — בונה קובץ Word עם `python-docx` (טבלת קריטריונים + ציון כללי + פסקת סיכום, כל הפסקאות מיושרות RTL).
- JSON שמור כולל `evaluation` ב-roundtrip: בטעינה הבדיקה מוצגת אוטומטית.

**Frontend** (`templates/index.html`):
- תפריט "שמור ▾" מאחד שלוש פעולות (מפוענח JSON / בדיקה JSON / בדיקה Word).
- שורת actionbar שנייה (רק עם pages): בורר רובריקה + "+ הוסף רובריקה" + "בדוק תרגיל".
- מודאל הוספת רובריקה (שם + textarea לתוכן).
- סקציית בדיקה: ציון כללי + פסקת סיכום + טבלת קריטריונים. מופיעה אחרי בדיקה או בטעינת JSON ששמר בדיקה.

**Desktop** (`desktop.py`): נוסף `save_docx` ל-API הנייטיב (Base64-encoded bytes מהדפדפן → קובץ דרך native dialog).

### בעיות שטיפלנו בהן בסשן
1. **HF Space אוטו-deploy לא עבד**: ניסינו GitHub Action שיסנכרן את `haskala/` ל-Space ב-push. דרש HF write token; חשבון אוריhttp ב-HF הוא Google-OAuth-only, ולכן כדי ליצור token מבקש סיסמה — שלא הייתה לו. ניסינו להגדיר סיסמה דרך settings, אבל "Confirm your identity" סירב לקבל אותה אפילו אחרי שינוי. **החלטה**: לוותר על auto-deploy ולחזור להעלאה ידנית. הוסר ה-workflow מהריפו.
2. **Dockerfile לא העתיק את `rubrics/`**: ה-Space רץ אבל הציג "אין רובריקות". תוקן בהוספת `COPY --chown=user rubrics/ rubrics/`.
3. **שגיאת JS `Cannot read properties of null (reading 'addEventListener')`**: ה-`<div id="rubric-modal">` היה מתחת לסקריפט שניסה לחבר אליו listeners. הועבר אל תוך בלוק `{% if pages %}` לפני ה-IIFE.

## מצב כרגע

- **GitHub** (`fun` repo) מעודכן עם כל הקוד החדש.
- **HF Space** (`orimosenzon/haskala-ocr`) מעודכן ידנית עם `app.py`, `requirements.txt`, `templates/index.html`, `rubrics/esl-9th-grade-analytical.json`, `Dockerfile`. הריצה היחידה שלא אומתה end-to-end היא תיקון המודאל (`templates/index.html` האחרון) — צריך להעלות שוב ל-HF ולוודא ש"שמור בדיקה כקובץ Word" עובד.

## חוב טכני / רעיונות פתוחים

- **רובריקות מתווספות דרך ה-UI נמחקות ב-restart של HF Space** (filesystem זמני). כל רובריקה קבועה צריכה להעלות ידנית ל-`rubrics/` בקבצי ה-Space.
- **DEPLOY.md מיושן** — לא עודכן בסשן הזה. עדיין מתאר git push ל-HF.
- **GitHub Action ל-HF auto-sync** — אם אי-פעם יש סבלנות להגדיר סיסמה אמיתית ב-HF + יצירת token, אפשר לשחזר את הקובץ מה-git log.
- **חיתוך שורות** (הנושא הגדול מהסשן הקודם) — לא נגענו בו בסשן הזה.

## צעדים הבאים מומלצים
1. להעלות ל-HF Space את `templates/index.html` האחרון (תיקון המודאל) ולוודא בדיקה→Word עובדת.
2. לחזור לבעיית חיתוך השורות (#2 מהסשן הקודם) — עדיין בעיית האיכות הגדולה.
3. כיול בחירת המודל (Claude מול Gemini) על מדגם תרגילים אמיתיים.
