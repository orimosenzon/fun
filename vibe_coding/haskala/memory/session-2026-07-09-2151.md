## חסם — לא הצלחנו לאמת שזה עובד בפועל
בדיקה דרך "Test in Cloud Shell" (curl עם identity token ל-URL הציבורי)
החזירה **503 — "Service is disabled"**. נבדק ונשלל: Ingress מוגדר `All`
(לא הבעיה). **השערה חזקה:** זו אותה בעיית מדיניות ארגונית שכבר חוסמת
checker/math-checker (org policy) — כי **כל פקודת gcloud** בסשן הזה, כולל
כאלה שהצליחו, הדפיסה את האזהרה:
```
Regional Access Boundary HTTP request failed after retries:
response_data={'error': {'code': 404, 'message': 'Account not found for
email: 208dd612cc|ori@bdika.net', 'status': 'NOT_FOUND'}}
```
זה מרמז על מדיניות Access Context Manager / regional access boundary
שבורה ברמת הארגון, שמזהה את אורי לפי מזהה פנימי (`208dd612cc`) ולא מוצאת
אותו — ל-API calls של gcloud זו רק אזהרה, אבל יכול להיות שהיא **חוסמת
בפועל** קריאות HTTPS ישירות ל-`*.run.app`.

**לא נבדק עדיין:** האם יש כבר Eventarc/Cloud Scheduler trigger מחובר
ל-scan2 (לשונית Triggers לא נבדקה) — ייתכן שההרצה האמיתית לא עוברת דרך
אותו נתיב חסום.
