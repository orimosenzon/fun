# math-checker — ידע על המוצר

## מהות
מוצר #2 של חברת השכלה (ראה `../../company-knowledge.md`). בדיקת תרגילי **מתמטיקה**
בכתב יד — נפרד לחלוטין מבודק-השפה (`../checker`).

## למה מוצר נפרד ולא הרחבה של checker (החלטה 2026-06-16)
בדיקת מתמטיקה היא **לא בעיית שורה-שורה**. תרגיל מתמטי הוא יחידה הוליסטית: סרטוטים,
הוכחות גאומטריות, ומעברים אלגבריים פרושים ב-2D. מודל ה-line-by-line של checker
(חיתוך שורות + alignment) הורס את המבנה. לכן: הבנה הוליסטית של העמוד כשלם.

## ארכיטקטורה (MVP)
- **סטאק:** Flask + Anthropic SDK + pymupdf (PDF→image) + Pillow. UI: HTML + **KaTeX**.
- **פורט:** 5051 (checker על 5050).
- **זרימה:** העלאת PDF/תמונה → render לעמודים → תיקון אוריינטציה (Haiku, 0/90/180/270)
  → ניתוח הוליסטי (Opus) שמחזיר JSON מובנה → רינדור KaTeX לצד העמוד המקורי.
- **מודלים:** `claude-opus-4-8` לניתוח, `claude-haiku-4-5` לזיהוי סיבוב.
- **סכמת ניתוח:** page_summary, has_diagram, problems[] עם student_steps[] (LaTeX+ok+comment),
  verdict (correct/partial/incorrect/unclear), feedback.

## למה תיקון 180° חשוב
ב-checker `auto_rotate` בודק רק portrait/landscape ולא מזהה היפוך 180°. בבדיקה על
מבחני הדוגמה (2026-06-16) עמודים 3,5 (סרוקים הפוכים) יצאו ג'יבריש. כאן צעד Haiku ייעודי.
