### 2. שכבת dispatch רב-ספקית (app.py)
- `MODELS` (key→תווית) + מפות `_ANTHROPIC_IDS`/`_GEMINI_IDS`/`_GROQ_IDS`/`_AZURE_KEYS`.
- `resolve_model` עכשיו מחזיר **(key, label)** במקום (model_id, label). כל ה-pipeline
  (`_process_stream`/`_run_job`/`analyze_start`/`reanalyze`) עבר ל-`model_key`.
- `analyze_page(img, model_key)` מנתב ל-`_analyze_anthropic`/`_analyze_gemini`/
  `_analyze_groq`/`_analyze_azure`. כולם מחזירים אותו מבנה JSON (ANALYSIS_SCHEMA).
- קליינטים lazy (`_gemini`/`_groq`/`_azure`) — מפתח חסר מפריע רק אם בוחרים את הספק.
- זיהוי סיבוב נשאר תמיד Haiku (זול).
- **Gemini:** `_GEMINI_SCHEMA` = ANALYSIS_SCHEMA בלי `additionalProperties` (Gemini דוחה
  את המפתח). `max_output_tokens=24000` כי thinking של Gemini 2.5 נספר בתקציב וקיטע JSON.
- **Groq/Azure:** OpenAI-compatible, `response_format=json_object` (בלי schema) →
  `_JSON_CONTRACT` בטקסט מתאר את המבנה. helper משותף `_analyze_openai_compatible`.
- helper חדש `_jpeg_bytes` (ש-`_img_to_b64_jpeg` עכשיו עוטף).
