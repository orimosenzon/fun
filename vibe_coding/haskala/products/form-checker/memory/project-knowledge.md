# form-checker — ידע פרויקט

מוצר #5 של השכלה. בדיקת תרגילים שמורים שולחים דרך **טופס גוגל**, והדוח חוזר אליהם במייל.

נוצר: 2026-08-02.

## מה זה

מורה לאנגלית ממלא טופס גוגל — מעלה סריקה של תרגיל, ובוחר לפי איזו רובריקה לבדוק,
איזו שכבת גיל, איזה בית ספר, שמו. השירות מזהה את השורה החדשה, בודק את התרגיל,
ושולח דוח Word למייל שברשומה.

הטופס עצמו נכתב ע"י **אבישי** ומיועד להישלח למורים לאנגלית — כולל מחוץ לשמיר.

## למה זה לא oris-scanner

אותו מנוע בדיקה בדיוק, קלט ופלט אחרים:

| | oris-scanner | form-checker |
|---|---|---|
| קלט | Google Classroom (הגשות תלמידים) | טופס גוגל (מורה שולח) |
| מי שולח | תלמיד | מורה |
| רובריקה | רובריקת Classroom / קובץ מצורף | dropdown בטופס |
| פלט | קובץ בתיקיית Drive | מייל למורה |
| תדירות | `*/1` — מורה מחכה | `*/5` — אף אחד לא מחכה |
| שם קובץ | בלי חותמת זמן (בקשה מפורשת) | **עם** חותמת זמן |

חותמת הזמן בשם הקובץ היא ההבדל שקל לפספס: הגשה ב-Classroom היא ניסיון אחד של
תלמיד אחד, אז התנגשות שם = הגשה חוזרת. מורה שמנסה את הטופס שולח את אותו תרגיל
חמש פעמים בעשר דקות, ותיבת דואר עם חמישה קבצים באותו שם היא חסרת ערך.

## ארכיטקטורה

```
Cloud Scheduler (*/5)
  └─ Cloud Run: form-checker  (--function=process_form_responses)
       ├─ Sheets API  → גיליון התשובות של הטופס
       ├─ form_schema → מיפוי כותרות → פרמטרי בדיקה
       ├─ Firestore   → ledger למניעת בדיקה כפולה (form_checker_responses)
       ├─ Drive API   → הורדת הקבצים שהמורה העלה
       ├─ haskala_grading.core.check_pages   → OCR + הערכה
       ├─ haskala_grading.report             → docx
       └─ Gmail API   → שליחת הדוח (fallback: כתיבה ל-Drive)
```

מודולים: `main.py` (כניסה, auth, ledger, מכסות), `form_schema.py` (מיפוי הטופס),
`checker.py` (הדבק), `mailer.py` (משלוח). `tests/test_form_schema.py` — 22 טסטים,
רצים בלי רשת (`python tests/test_form_schema.py`, או pytest אם מותקן).

## תנאי מוקדם קריטי — מי הבעלים של הטופס

**טפסי גוגל שומרים קבצים שהועלו ב-Drive של בעל הטופס.** השירות קורא Drive בתור
`ori@bdika.net` דרך domain-wide delegation. לכן הטופס חייב להיות בבעלות חשבון
ב-Workspace של `bdika.net`.

אם אבישי בונה את הטופס בחשבון שמיר שלו — כל ההעלאות נוחתות ב-Drive שלו, השירות
לא רואה אותן, **ואין תיקון חוץ מבניית הטופס מחדש**. זה הדבר הראשון לוודא איתו.

בנוסף בהגדרות הטופס: לאפשר תשובות מחוץ לארגון (אחרת מורים מבתי ספר אחרים לא
יכולים לשלוח בכלל), ולוודא שיש מקום אחסון ב-Drive של בעל הטופס.

## החלטות תכנון

**מיפוי עמודות לפי טקסט הכותרת, לא לפי מיקום.** אבישי ימשיך לערוך את הטופס.
אינדקסים זזים בשקט — קריאת "עמודה D" הייתה מעבירה את תוכן עמודת הרובריקה
לפרמטר שכבת הגיל ובודקת לפי מחוון שגוי בלי שום דבר חשוד בלוגים. התאמה על טקסט
הופכת את אותה עריכה או להתאמה נכונה או לכישלון רועש.

**ההתאמה הארוכה ביותר מנצחת.** "שפת התרגיל" ו"התרגיל לבדיקה" שניהם מכילים
"תרגיל"; כלל ראשון-מנצח היה ממפה לפי סדר השאלות בטופס. יש טסט על זה.

**`form_schema.py --template`** מדפיס את כותרות השאלות ואת אפשרויות ה-dropdown
המדויקות. זו הדרך הנכונה לבנות את הטופס — לתת לאבישי את הפלט. הנדסה לאחור של
המיפוי מטופס קיים היא הדרך שמייצרת אי-התאמות שקטות.

**מפתח ה-ledger הוא hash של התוכן** (חותמת זמן + מייל + רשימת הקבצים), לא מספר
השורה. הוספה או מחיקה של שורה מזיזה כל מספר מתחתיה — זה היה גורם לבדיקה מחדש
של כל הגיליון. תשובה שנערכה מקבלת hash אחר, נכנסת כרשומה חדשה, ונבדקת שוב —
וזו בדיוק ההתנהגות הרצויה.

**שני נדבכי scopes.** `BASE_SCOPES` (spreadsheets.readonly, drive) מול
`EXTRA_SCOPES` (gmail.send). DWD היא הכל-או-כלום לכל בקשת token: scope אחד לא
מאושר מפיל את כל הבקשה עם `unauthorized_client`. זה הפיל את oris-scanner לגמרי
ב-2026-07-30. משלוח מייל לעולם לא יפיל בדיקה — בלי scope המייל, השירות עדיין
בודק וכותב ל-Drive.

חשוב: זה **לכל בקשת token**, אז scope שform-checker מבקש ו-oris-scanner לא —
לא יכול להשפיע על oris-scanner. הוספת scopes לרשומת ה-DWD המשותפת היא מצטברת
ובטוחה.

## מכסות עלות

טופס פתוח למורים הוא דלת פתוחה להוצאה, והפרויקט כבר שילם פעמיים
(~$20 ביולי בלי dedup, ~$26 על סופת retry ב-Pub/Sub).

- `MAX_PAGES_PER_RESPONSE` (20) — **זו המכסה שבאמת חוסמת את החשבון.** כל עמוד
  הוא קריאת rotation + קריאת OCR + חלק מקריאת ההערכה, ~$0.04–0.06 לעמוד ב-Sonnet 5.
  נספר עם fitz לפני כל rasterization.
- `MAX_FILES_PER_RESPONSE` (10), `MAX_ROWS_PER_RUN` (5).
- `FORM_CHECKER_ALLOWED_DOMAINS` / `FORM_CHECKER_PASSPHRASE` — שניהם ריקים
  כברירת מחדל, כלומר כל מי שיש לו את הלינק. מודפסת אזהרה בכל סריקה. **חובה
  להגדיר אחד מהם לפני שהלינק מופץ.**
- ledger עם תקרת 3 ניסיונות — אותו circuit breaker שעצר את לולאת ה-OOM של
  oris-scanner ב-2026-07-28 (~40 ניסיונות בלילה על קובץ אחד).

דחיות גישה (דומיין/סיסמה) **לא** מחזירות מייל בכוונה: תשובה הייתה הופכת את
הטופס לדרך לשלוח דואר לכתובת שרירותית.

## מצב

הקוד כתוב ונבדק מקומית (22 טסטים + dry-run מול Sheets מזויף + יצירת docx אמיתי).
**עדיין לא נפרס ולא רץ מול טופס אמיתי.** מה שחסר לפני פריסה ראשונה:

1. `gcloud auth login` (היה תקוע בשלושה סשנים ברצף).
2. הטופס עצמו — אבישי, בבעלות חשבון bdika.net. לתת לו את פלט `--template`.
3. שני ה-scopes ברשומת ה-DWD (client id `114647217076557059736`):
   `spreadsheets.readonly` ו-`gmail.send`.
4. `RESPONSES_SHEET_ID` ו-`FALLBACK_RESULTS_FOLDER_ID` ל-deploy.sh.
5. `./deploy.sh` ואז `./setup_infra.sh` פעם אחת.
