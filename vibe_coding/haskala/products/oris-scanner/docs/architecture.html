מה בעצם מריץ את הקוד

oris-scanner · Cloud Run · europe-west1

הדבר החשוב להבין ראשון: בין בדיקה לבדיקה שום תהליך שלך לא רץ. אין שרת שמאזין, אין לולאה שממתינה. Cloud Run מחזיק תמונת מכולה (container image) רדומה, ומעיר אותה רק כשמגיעה בקשת HTTP. כשהבקשה נגמרת — המכולה חוזרת לישון. זו הסיבה שאתה משלם רק על שניות עבודה בפועל, וזו גם הסיבה שצריך מישהו חיצוני שידפוק בדלת.

שרשרת ההעָרה — מי דופק בדלת

1 Cloud Scheduler cron מנוהל
משימה בשם oris-scanner-poll עם לוח זמנים */5 * * * *. זהו cron מנוהל של גוגל — הוא לא מריץ קוד, הוא רק שולח בקשת רשת בזמנים קבועים. אין לו מושג מה יש בצד השני.
↓ POST · גוף ריק · חתום ב־OIDC
2 שער הכניסה של Cloud Run אימות
השירות פרוס עם --no-allow-unauthenticated, כלומר סגור לאינטרנט. הסקדיולר מצורף ל־service account שקיבל את התפקיד roles/run.invoker, וחותם כל בקשה בטוקן OIDC (OpenID Connect — שכבת זהות מעל OAuth 2.0: תעודה חתומה שאומרת "אני זה־וזה", לעומת טוקן OAuth רגיל שאומר רק "מותר לי"). ה־audience של הטוקן הוא כתובת השירות עצמה, כך שטוקן שדלף לא יעבוד מול שירות אחר.
↓ הבקשה אושרה
3 הרמת המכולה cold start
אם אין מכולה חיה, Cloud Run מרים אחת: 1 vCPU, 512 MiB, startup-cpu-boost דלוק כדי לקצר את ההתנעה. בפנים עולה functions-framework — עטיפה שמקימה שרת Flask ומנתבת כל בקשה לפונקציה אחת שהוגדרה בדיפלוי: --function=process_my_drive_files.
↓ קריאה לפונקציה
