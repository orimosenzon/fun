## 2. Domain-wide delegation scope authorization (blocking issue, now resolved)
Deploying the new scope broke the **entire** service immediately — not just the topics call.
Every `run_workspace_scan()` failed at the very first Classroom call
(`courses().list()`) with:
```
unauthorized_client: Client is unauthorized to retrieve access tokens using this method,
or client not authorized for any of the scopes requested.
```
Root cause: domain-wide delegation requires the **full combined scope set** to be
pre-authorized in the Workspace Admin Console for the client ID — requesting a token with
even one unauthorized scope in the list fails the whole grant, not just that scope's calls.

Walked Ori (non-technical on this specific flow) through authorizing it live, screenshot by
screenshot: admin.google.com → Security → API controls → Domain-wide Delegation → client ID
`114647217076557059736` (`sainter@master-gecko-500709-t0.iam.gserviceaccount.com`) → added
`https://www.googleapis.com/auth/classroom.topics.readonly` alongside the 3 existing scopes →
Authorize. Confirmed via Cloud Run logs: errors stopped appearing after ~12:04 UTC.
