## 1. Cloud Run mechanics — measured, and documented for good

Ori asked how the service is actually triggered. Everything below was measured
against production, not inferred from the code.

- **Trigger chain**: Cloud Scheduler `oris-scanner-poll` → HTTP POST (empty body,
  OIDC-signed) → Cloud Run → functions-framework/Flask → `process_my_drive_files`.
- **No parameters travel in the request.** The `request` argument is accepted and
  ignored; the POST is a doorbell. Config comes from three places: env vars
  (`--set-env-vars`), Secret Manager (`--set-secrets`), and Classroom itself
  (description = question, `[model: …]` tag, rubric, attachments) — the last being
  the only one a teacher can change without a deploy.
- **Idle scan ~6.0s**, 15 Classroom API calls, ~5.5 Firestore reads.

**Classroom quota question — CLOSED** (open since 07-23). Real limits pulled from
the Service Usage API: 600 req/min/project/**user** is the binding one (all calls
go through one delegated user); 3,000/min/project and 4M/day/project are far away.
At `*/1` we used 15 — **2.5%**. Never a real risk.

## 2. Poll rate `*/1` → `*/5`

| | `*/1` | `*/5` |
|---|---|---|
| requests/month | 43,830 | 8,766 |
| vCPU-s/month | 262,980 | ~52,600 |
| cost | ~$2/month | **$0** (inside free tier) |

Key point that decided it: **`*/15` costs exactly the same as `*/5`** (both fully
inside the free tier) while tripling the wait, so `*/5` is the floor worth taking.
Caveat recorded in `setup_infra.sh`: the free tier is shared with
`checker`/`scan1`/`scan2`; if they consume it this costs ~$1.3/month, not zero.

Observed after the change: scan latency rose 6.0s → 7–8.6s, because at 5-minute
gaps the instance is reaped between polls and each scan pays container startup.
Does not change the cost conclusion.

**Drift found:** the 07-23 note claimed `setup_infra.sh`'s `SCHEDULE` default was
changed to `* * * * *`. It was not — only the live job was. Lesson: a change that
touches both `gcloud` and the repo is easy to half-do and fully document.

## 3. Unnamed rubric attachments — content-based routing

Problem: a rubric attached as a plain PDF was ignored, because
`resolve_rubric_material` matched on filename only. Teachers don't rename files.

Constraint that shaped it: a material rubric **replaces** the bundled one, so
blindly adopting any PDF drops the score scale whenever the attachment is an
assignment brief. Ori chose content-based routing over "always treat it as a rubric".

- `core.resolve_rubric_material` — step 3: a **lone** Drive attachment is adopted
  with `certain=False`. Several unnamed → no guess + warning.
- `core.classify_document(text, model_key)` — one short text-only call, all four
  providers, mirrors `detect_rotation`. Defaults to `assignment` on any doubt.
- `checker.load_material_rubric` returns `kind`; `check_hw` folds an `assignment`
  document into the question and leaves the bundled rubric in place.

Verified: 10 offline cases + 5 live against real Gemini, including the trap case
(a "how to build a rubric" guide → correctly `assignment`).

**Still unproven in production** — the one real submission went down the old
name-match path, because `rubric` is in the filename.

## 5. PRODUCTION INCIDENT — OOM loop (the important one)

Avishai submitted at 2026-07-28 18:07. No report appeared. Root cause:

```
Memory limit of 512 MiB exceeded with 903 MiB used
```

A **single-page** 2.1MB PDF (a photo whose page renders large at 200 DPI) pushed
the container past 900MiB and got it OOM-killed mid-check. The claim stayed
`in_progress`, went stale after 20 min, was reclaimed, and died again — **41 OOM
kills between 18:10 and 09:10, 10 attempts in the last 4 hours alone, 0 reports.**

Two fixes:

1. **Memory 512Mi → 2Gi.** Cleared it on the first attempt: graded in 23s, 1 page,
   126 words, report uploaded. Pinned in `deploy.sh` so a rebuild can't regress.
2. **Retry ceiling** — `_MAX_GRADING_ATTEMPTS = 3` with an `attempts` counter in the
   Firestore ledger. Past the ceiling the submission is parked as `failed` with an
   ERROR log line. A changed `updateTime` (resubmission) resets the counter, so it's
   a circuit breaker on a broken *version*, not a blacklist. 17 offline cases pass,
   including that the 07-26 regrade-on-resubmission fix still works.

**Why this mattered more than it looked:** on free Gemini the loop only burned
quota. Those same 41 attempts on Claude Sonnet 5 (~$0.04 each) would have been
**~$1.70 — a third of a $5 balance, on one file, overnight, unattended.** The
ceiling was shipped in the same deploy as the paid provider, deliberately.

Sequencing used: raise memory first, verify with the **free** model, only then
deploy Claude. Worth repeating for any future paid-provider change.

## 6. Claude Sonnet 5 is now the default

Ori topped the Anthropic account to $5 and asked for Sonnet 5 as default.

- `_ANTHROPIC_MODEL = "claude-sonnet-5"`, `DEFAULT_MODEL = "claude"`.
- **`thinking={"type": "disabled"}` on all four Anthropic call sites — load-bearing.**
  On Sonnet 5 adaptive thinking is ON when `thinking` is omitted (it was OFF on
  Opus 4.8), and `max_tokens` caps thinking *plus* text. The two `max_tokens=10`
  calls (`detect_rotation`, `classify_document`) would have returned empty strings:
  every page read as unrotated, every unnamed attachment classified as
  "assignment" — with no error anywhere.
- Sonnet 5 rejects `temperature`/`top_p`/`top_k`/`budget_tokens` with a 400; none
  of the call sites used them, so the migration was the model id plus these flags.

**Cost estimate** (~10,150 input + ~2,310 output tokens per single-page submission):
**~$0.043** at the intro rate ($2/$10 per MTok, through 2026-08-31), **~$0.065** at
standard ($3/$15). $5 ≈ 115 submissions now, ~77 later. Not yet replaced with a
measured figure — **Sonnet 5 has still never made a real call.**

## 7. Model tag — verified, and one alias bug fixed

`[model: …]` / `[מודל: …]` / `[model=…]` in the assignment description. Tested 9
teacher-plausible inputs offline: all correct, including that innocent brackets
(`[see page 4]`) are not stripped.

**Bug the test exposed:** `opus` and `claude-opus` were aliases for the `claude`
key, which had just been repointed from Opus 4.8 to Sonnet 5 — so
`[model: opus]` would have silently graded with Sonnet. Removed them (unmapped →
visible "unknown model" warning + default) and added `sonnet` / `sonnet-5` /
`claude-sonnet`.
