## 1. Submission trace logging
Structured logging across `main.py` / `checker.py` / `core.py`, every line stamped with
`[subm <id>]` so one submission can be followed through interleaved concurrent runs.
Logged: detection (course, assignment, state, student, late, updateTime), the claim/dedup
decision, folder resolution, each attachment downloaded with size/type, then a parameter
block printed **before** the slow model calls — assignment, model, rubric source, rubric
name, the question, and the rubric text itself (previewed, newlines flattened to `⏎`).
Finishes with per-page OCR, eval result and elapsed time.

Two levels: INFO is the story of an actual grading and is silent in steady state; DEBUG is
the once-a-minute polling chatter (nothing new, drafts, already-graded). At 1-minute polling
DEBUG would otherwise bury the one trace worth reading. Controlled by `LOG_LEVEL`, pinned in
`deploy.sh` (default INFO) because `--set-env-vars` replaces the whole env block, so a
hand-set value gets silently wiped on the next deploy.

### Two bugs found only by actually running it
- **Severity was never set.** Plain-text log lines arrive in Cloud Logging as severity
  DEFAULT, so `severity>=INFO` matched *none* of them — the first version of `logs.sh`
  returned only Cloud Run's own access logs. Fixed with `_CloudLoggingFormatter`, one JSON
  object per line (`severity`/`message`/`logger`), which Cloud Run parses. `ensure_ascii=False`
  keeps Hebrew readable.
- **DEBUG was unusable** — `urllib3`/`googleapiclient` logged every HTTP request and
  connection. Those loggers are now pinned to WARNING; `discovery_cache` alone had been
  printing two useless lines per poll even at INFO.

Also: `checker.py`'s import-time `basicConfig` removed (a module `main` imports must not own
logging config, or `main`'s own setup becomes a silent no-op), and `process_my_drive_files`
now logs the traceback before re-raising, since Cloud Scheduler only ever sees a status code.

### New: `logs.sh`
`-f` follow, `-n` limit, `-s 30m|2h|3d` lookback, `-d` include DEBUG, `-e` errors only,
`-g <text>` isolate one submission's trace. Adds `~/google-cloud-sdk/bin` to PATH itself
(the SDK is a user-directory install, only on PATH in interactive shells), and spells out
relative times because GNU `date` rejects the `-2h` shorthand. Filter is restricted to the
app's own stdout/stderr, excluding the empty per-poll access-log entries.

## 2. Teacher-selectable model — `[model: …]` tag
Classroom exposes no free metadata field on a courseWork, so the only channel through the
normal UI is text the teacher already types. `core.resolve_model()` reads a tag out of the
assignment description and **strips it out** before the description is used as the question,
so the grader never sees it. Accepts `[model:…]`, `[מודל:…]`, `=` for `:`, any casing, and
aliases (`gpt`→`azure-gpt41-mini`, `opus`→`claude`, `scout`→`groq-scout`, …). An unknown
name falls back to the default **and logs a warning listing valid keys** — silently grading
with the wrong model is worse than saying so. The value must start with a non-space char so
a phrase like `[model: ]` isn't mistaken for a tag and deleted from the assignment text.

Tradeoff accepted: the tag is visible to students in Classroom.

## 4. Rubric attached as a document (the "I did attach a rubric" confusion)
Ori attached a rubric **PDF** to the assignment and expected it to be used. It wasn't, and
the code was right: Classroom's native **rubric** (`courses.courseWork.rubrics`) and a
**material attachment** (`courseWork.materials[]`) are entirely different things. The
production log line `rubric src : bundled default` *was* the API verification — `rubrics.list`
returned empty.

Now supported as a third rubric source. Precedence: native Classroom rubric → attached
document → bundled default.
- `core.resolve_rubric_material()` picks the attachment: an explicit `[rubric: <text>]` tag
  first, otherwise a filename containing `rubric` / `רובריקה` / `מחוון`. If nothing matches
  it **does not guess** — a wrong rubric is worse than the generic default, since it would
  silently grade against a worksheet.
  Tag matching is whole-word first, substring second: `[rubric: B]` must select
  `rubric B.pdf`, not `rubric A.pdf` where the letter b merely sits inside "rubric".
- `core.rubric_text_from_document()` reads a digital PDF's text layer (instant, exact, zero
  model calls) and only falls back to vision OCR for a scanned one. Threshold 100 chars —
  set too high, compact but readable rubrics get a needless billable vision pass.
- `checker.load_material_rubric()` downloads it (Google Docs are exported as text/plain) and
  never lets a failure take the submission down — any error falls back to the bundled rubric.
- Read **once per assignment per scan and only when there is something to grade**, not per
  student and not on every one-minute poll.

Both extraction paths were tested separately, the OCR one against the real Gemini key.

## 5. Bug found: resubmissions were never regraded
The Firestore ledger keyed on submission id, which Classroom keeps **stable** across
unsubmit/resubmit. Once marked `done` it was skipped forever — so a student who reworked and
handed in again was never regraded, silently, contradicting the `RETURNED` case the scan
explicitly accepts. It also blocked Ori from re-testing at all.

Fix: `done` is now recorded together with the submission's `updateTime`, and a changed
`updateTime` reopens it. Legacy entries without a version are **backfilled without
regrading** — otherwise every already-graded submission would regrade the moment it shipped;
verified in the log that nothing fired after deploy. All eight branches of the claim logic
were tested against an in-memory Firestore stand-in before deploying.

**Hazard recorded in the code:** if draftGrade writing is ever added, writing a grade bumps
`updateTime`, which looks like a resubmission → regrade → write → loop, one model call each
turn. Whatever writes the grade must record the resulting `updateTime`.
