## 1. Trigger mechanism: Pub/Sub → Cloud Scheduler + direct HTTP
Ori questioned why the pipeline used Pub/Sub at all instead of a plain HTTP call. Conclusion: Pub/Sub
was inherited from scan2's design (relevant if using Classroom's push-notification `Registrations`
API, which requires a Pub/Sub topic target) — but that path was explicitly rejected last session in
favor of polling. For polling, Pub/Sub added a second retry/redelivery system stacked on top of
Cloud Scheduler's own, for no benefit — the same class of mechanism that caused the original scan2
cost incident.

**Changes (commits `b7ebef0`, `6178e1c`, `fd3ec73`, `84d82b2`, `e314e02` — all pushed):**
- `main.py`: `process_my_drive_files` changed from `@functions_framework.cloud_event` to
  `@functions_framework.http`.
- `setup_infra.sh`: rewritten — creates Cloud Scheduler job `oris-scanner-poll` (every 15 min,
  chosen over 5/60 min options) instead of Pub/Sub topic/subscription/dead-letter. Retry settings
  mirror the old Pub/Sub config (attempt-deadline 600s, fixed 600s backoff, max 5 attempts).
- Deleted old Pub/Sub resources: topic `orisScanNow`, subscription `oris-scanner-sub`, dead-letter
  topic `oris-scanner-dead-letter` + its sub. Confirmed scan2's/checker's own Pub/Sub resources
  (`scanNow`, `checkNow`, `scan2-dead-letter`, etc.) were left untouched.
- Verified end-to-end on real infra: manually confirmed the scheduler's first automatic fire
  (05:45:00 UTC) hit Cloud Run and returned HTTP 200.

## 4. Removed the allowlist entirely, added per-assignment Drive subfolder, then re-narrowed
Ori's design change, in two steps:

**Step 1 — widen:** drop `TARGET_COURSEWORK_IDS` completely; scope by
`courses.list(teacherId='me')` instead, then process every courseWork in every course the delegated
account teaches. Ori explicitly chose "every assignment, no exceptions" over a coarser course-type
filter when asked, accepting that non-language assignments (e.g. geometry) in the same course would
also get language-graded.

Also added, per Ori's request: `_get_or_create_coursework_folder()` — creates a Drive subfolder
under `RESULTS_FOLDER_ID` once per courseWork (named `"{course name} — {assignment title}"`),
mapping kept in a new Firestore collection `oris_scanner_coursework_folders` so every run reuses the
same folder. Not fully race-proof (two overlapping first-encounters could double-create) — accepted,
harmless duplicate at worst.

Deployed (`oris-scanner-00010-l6z`) and manually triggered. **Verified working end-to-end**: Ori's
submission was OCR'd (15 lines), evaluated (ESL rubric, 4 criteria, overall "A2 to B1"), and
`gali goldkorn_report_20260722-092849.docx` landed in the correct new per-assignment folder
(confirmed both via Cloud Run logs and by reading the Firestore folder-mapping doc directly, since
Ori's local `gcloud` token lacks Drive API scope — Firestore reads worked, Drive reads returned 403
insufficient-scope).

**Fallout from widening:** the same run picked up 4 courseWork items in the "integration" course
(confirmed via the `oris_scanner_coursework_folders` docs), including courseWork `868721455582`,
"תרגיל בגאומטריה" (geometry) — exactly the accepted-tradeoff scenario, now live. That submission's
OCR call hit Gemini's **free-tier per-minute** limit (5 req/min) on the first attempt, then Cloud
Scheduler auto-retried it ~90 min later and hit the **free-tier per-day** limit instead
(`GenerateRequestsPerDayPerProjectPerModel-FreeTier`, quota value **20**, for `gemini-2.5-flash`).
Confirmed via the actual Google API error payload, not inferred. This means the project is on the
free AI Studio key (`generativelanguage.googleapis.com`), not billed Vertex AI — real production use
(multiple students/courses) will exceed 20 requests/day almost immediately (each submission costs
2-3+ calls). Ori was informed there's no cost risk on the free tier itself (429s are $0), but a
paid-tier cost conversation is still pending — not yet had.

**Manual cleanup:** patched the stuck geometry submission's Firestore doc directly via the Firestore
REST API (PATCH, using Ori's own `gcloud auth print-access-token`) to `status: "done"` with a
`skip_reason` field, so it stops being retried. This is an out-of-band manual edit, not a code
change — worth remembering it exists if that submission doc ever needs re-inspection.

**Step 2 — re-narrow:** Ori decided the "every course" scope was too broad without a real
subject/language filter, and asked to at least cap it to the known "integration" course for now.
Added `TARGET_COURSE_NAME = "integration"` and filter courses by `course.get('name') ==
TARGET_COURSE_NAME` right after the `teacherId='me'` list call. Committed (`e314e02`) and deployed
(`oris-scanner-00011-fhk`) — this is the **currently live** revision.
