# Session 2026-07-22 (21:54) — checked-folder nesting fix, multi-provider wiring, live Groq outage discovered and worked around

## 1. Checked-report folder now nests inside the submission's own assignment folder
Ori's expectation was a "checked exercises" subfolder inside the folder Classroom already
auto-created for the assignment (shown in a screenshot) — instead the code was creating a
**parallel** folder tree under a separate hardcoded `RESULTS_FOLDER_ID` root, named
`"{course} — {assignment title}"`.

**Fix (`main.py`):** `_get_or_create_checked_folder()` replaces `_get_or_create_coursework_folder()`
— resolves the parent folder of the submission's own attached Drive file (`files().get(...,
fields="parents")`) and creates a `"תרגילים בדוקים"` subfolder there instead, still cached per
courseWork in the same Firestore ledger (`oris_scanner_coursework_folders`) so it's created once
and reused. `RESULTS_FOLDER_ID` kept only as `FALLBACK_RESULTS_FOLDER_ID`, used only if a file has
no resolvable parent.

**Important:** existing cached folder mappings (4 of them, from before this fix) were manually
deleted from Firestore so they'd regenerate in the new nested location — but the *submissions*
that already ran are separately marked `done` in `oris_scanner_submissions` and will never be
reprocessed just because of this folder change (dedup is keyed by submission id, independent of
folder location).

## 2. Wired all 4 checker/app.py model providers into oris-scanner
`core.py` already had full provider code (MODELS dict, dispatch for OCR + eval, clients) for
claude/gemini/gemini-lite/groq-scout/azure-gpt41-mini from an earlier port — but only
`GEMINI_API_KEY` was ever actually deployed to Cloud Run.

- Created Secret Manager secrets `groq-api-key`, `azure-openai-api-key` (values copied from
  `products/checker/.env`, which already had all 4 real keys). Reused existing `anthropic-api-key`
  secret (created 2026-07-09, previously unused by oris-scanner).
- Granted `roles/secretmanager.secretAccessor` on all 3 new-to-this-service secrets to the Cloud
  Run runtime SA (`311716089389-compute@developer.gserviceaccount.com`) — deploy failed with a
  permission error until this was done.
- `deploy.sh`: `--set-secrets` now includes all 4 API keys; added `--set-env-vars` for
  `AZURE_OPENAI_ENDPOINT`/`AZURE_OPENAI_DEPLOYMENT` (non-secret config).
- **Real bug found and fixed:** `detect_rotation()` was hardcoded to always call Gemini
  (`ORIENT_MODEL_KEY = "gemini"`) regardless of `DEFAULT_MODEL` — so switching the main model to
  dodge an outage would've silently still hit dead Gemini for page-rotation detection. Now takes
  `model_key` as a parameter (threaded through from `check_pages`), with new groq/azure branches
  added matching `ocr_page`'s dispatch pattern.

## 3. Groq's vision model is gone — discovered live, mid-incident
Set `DEFAULT_MODEL = "groq-scout"` first (free, seemed like the obvious unblock). Deployed, but
every real attempt then crashed: `groq.NotFoundError: 404 model_not_found` for
`meta-llama/llama-4-scout-17b-16e-instruct`. Checked Groq's `/v1/models` directly for this key —
**no vision-capable model exists in the current list at all** (only text/audio models remain:
llama-3.3-70b-versatile, gpt-oss variants, whisper, etc.). This isn't a fixable model-ID typo —
**Groq cannot currently serve as an OCR provider for this pipeline, structurally**, until/unless
they reintroduce a vision model. `groq-scout` should not be picked again without re-checking
Groq's model list first.

**Follow-up fix:** switched `DEFAULT_MODEL` to `"azure-gpt41-mini"` — confirmed working with a
direct test call before deploying. Redeployed successfully.
