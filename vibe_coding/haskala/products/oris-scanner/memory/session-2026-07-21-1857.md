## Key finding — Classroom attachment API is a dead end for "put the file where the teacher expects it"
Checked `courses.courseWork.studentSubmissions.modifyAttachments` directly against Google's own
reference docs: attachments can only be added by the same OAuth client / Developer Console project
that originally created the courseWork item. Since Yaron/Ori create assignments manually through
Classroom's own web UI (Google's first-party client), oris-scanner's own API client can never satisfy
this — confirmed this holds **regardless of the calling account's role in the course** (teacher vs
co-teacher makes no difference; the restriction is about which application made the request, not the
human's permission level within the course). This is a structural API limitation, not a permissions
setting that can be fixed by granting more access.

**Decided replacement plan (approved direction, not yet implemented):**
1. Write a numeric `draftGrade` directly onto the submission (shows right in the teacher's existing
   grading view — no attachment restriction applies to this field). Needs a fallback: the default
   rubric's `overall_score` is a CEFR string ("A2 to B1"), not a clean number, so this isn't
   automatic for every rubric.
2. Share the individual report file directly with the teacher (and maybe the student) via Drive's
   sharing API, instead of dropping everything into one shared folder nobody thinks to check —
   triggers Google's normal share notification/email.

Ori wants to think this over before it gets built — **not started**.
