# Session 2026-06-12 (10:30) — פתרון בעיית חיתוך השורות (הושלם ושולב)

## TL;DR
בעיית חיתוך השורות ההיסטורית נפתרה בשני מהלכים משלימים, והפתרון **שולב ב-app.py ועבר e2e**:
1. **דיטקטור שורות חדש** (`segmentation.py`) — עצמאי, לא תלוי בספירת ה-OCR.
2. **פרוטוקול overlay ממוספר** — על התמונה שנשלחת ל-OCR מצוירות קופסאות ממוספרות,
   והמודל מחזיר לכל שורת תמליל את מספר הקופסה שמכילה אותה (`{"n":7,"text":...}`).
   ההתאמה טקסט↔חיתוך נעשית ע"י הגורם היחיד שרואה את שניהם. **באגי off-by-one
   גלובליים בלתי-אפשריים by construction** — קופסת זבל פשוט לא ממופה.

## הדיטקטור (segmentation.py)
`paper_mask` (רוויה+בהירות — דף לבן מול שולחן עץ/ספרים) → `sauvola` אדפטיבי
(תופס עיפרון חיוור) → `remove_ruling` (ריצות ארוכות בשורות-עמוד, עט דק מוגן ע"י
פטור tall) → clip עמודה לפי ruling נרחב (≥5 קווים, ≥40% גובה) → `slope_deskew`
(הצבעת שיפוע על מרכזי רכיבים, ±24° — החליף את deskew_page שהוגבל ל-10° ולפעמים
הזיק) → פרופיל 1D, peaks חופשיים לפי prominence (בלי כפיית N) → פילטרים:
מסה, גובה (צללים), letter-ink (שורות ruled ריקות), אשכולות-y (זבל רקע מרוחק).
Over-detection מותר — הפרוטוקול בולע אותו.

## שינויים ב-app.py
- `import segmentation`; pipeline חדש: render → deskew(slope) → segment(detect+overlay)
  → ocr(overlay) → crop(לפי n). הסדר השתנה — segment לפני ocr.
- prompt: בלוק overlay (numbered=True/False), הוסר writing_region. סכמה: `lines:[{n,text}]`.
- כל 4 הספקים מקבלים numbered; gemini_schema של ה-OCR עודכן (n nullable).
- מסלול אנגלית: בלי overlay (numbered=False), בלי crops — כמו קודם.
- preview: `suggested_fine = -estimate_skew_angle` (החלפת deskew_page).
- **נמחק קוד מת:** deskew_page, _smoothed_profile, _writing_region, _prominence,
  segment_into_lines, crop_line.
- requirements.txt: + scipy.
