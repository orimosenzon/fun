# סשן 2026-06-02 09:30 — תמיכת מובייל ב-web app

## אופי הסשן
המשתמש דיווח שהכל עובד כצפוי אחרי השינויים מהסשן הקודם (בנר שגיאות, פלטת צבעים, Gemini Flash-Lite), וביקש שהאפליקציה תיראה ותעבוד טוב גם בגלישה מטלפון נייד. שינויים רק ב-`templates/index.html` — אין שינוי לוגיקת שרת.

## מה השתנה ב-`templates/index.html`

### CSS — שני breakpoints חדשים
- **`@media (max-width: 768px)`** — tablet + phone: מקטין padding של hero/actionbars/page-sections/eval-section, מסתיר `hero-art`, ה-`spacer` בתוך `.actionbar` מוסתר (כדי שכפתורים לא יידחפו מצדדים אחרי wrap).
- **`@media (max-width: 480px)`** — phone בלבד: מתאים touch targets ל-44px (`button { min-height: 44px }`, select-ים זהים), `.page-header` עובר ל-`flex-direction: column` כדי שהשם של הקובץ לא ידחוף את הכותרת, `.line` מקבל badge קטן יותר (26px במקום 32px), ה-`annotation-popup`/`modal` מקבלים `width: calc(100vw - 1rem)` ו-96vw.

### טבלת הערכה → קלפים במובייל
- ב-`<=768px`: `display: block` על table/tbody/tr/td, `thead` מוסתר, כל `<tr>` הופך לקלף עם `border-radius: 10px`. כל `<td>` מקבל label שמוצג ב-`::before { content: attr(data-label) }`.
- `criterion-cell` שומר על border-inline-start צבעוני (6px) — זה הסימן הויזואלי שמחבר את הקלף לקריטריון.
- `criterion-cell::before { display: none }` כדי לא לכפול את הכותרת.

### JS — `data-label` ל-render
ב-`renderEvaluation`, כל `<td>` נוצר עם `data-label` (קריטריון/ציון/פידבק/Feedback (EN)). זה מה ש-CSS שואב ב-`::before` כשהטבלה במצב קלפים. ב-desktop ה-label לא נראה כי `thead` עדיין מוצג והעמודות שמורות.

### Highlight tooltip — גם tap
- IIFE קיים שינוי: נוסף state `stickyEl` שמייצג tap-pinned.
- Hover רגיל ב-desktop נשמר; אם משהו "מוצמד" (stickyEl), hover מתעלם.
- Click handler חדש שמטפל ב-`.char.highlight` שאינו `.annotated` — מצמיד את הטולטיפ, ולחיצה שוב על אותו char או מחוצה מבטלת. הקריטריון: אם הוא annotated, ה-annotation popup לוקח אותו ולא נוצרת תחרות.
- `showTooltipFor` עכשיו מודד את `tipRect` אחרי `add('visible')` ותחם ל-`window.innerWidth`/`innerHeight`. אם יוצא למטה — היפוך מעל ה-char.

### Annotation popup — Y clamping
`positionPopup` עכשיו:
1. מוסיף `visible` קודם כדי שאפשר יהיה למדוד `offsetWidth/Height` אמיתיים (במובייל ה-CSS מצמצם את הרוחב ל-92vw, ה-280px default היה לא נכון).
2. אם בוטל ה-rectangle מתחת לחלון — היפוך מעל ה-anchor.
3. fallback: `scrollY + 10` (לפחות לוודא שנראה).

## אימות
Playwright + chromium emulation ברוחבים 320, 375, 390, 393, 768, 1280:
- `documentElement.scrollWidth <= window.innerWidth` בכולם (אין overflow אופקי).
- Tap על `.char.highlight` מצמיד tooltip; tap מחוץ מבטל.
- Tap על `.char.annotated` פותח את ה-popup, ה-popup ממוקם בתוך ה-viewport.
- Desktop @1280×900 עדיין מציג את הטבלה ב-4 עמודות (אין רגרסיה).

## החלטות
- **שני breakpoints, לא רק אחד** — 768 ל-tablet (טבלה הופכת לקלפים, כפתורים מתכווצים) ו-480 ל-phone (touch targets 44px, page-header מתערפל). הפרדה זו מאפשרת ל-iPad להיראות טבלאי בעוד שלטלפון יש קלפים.
- **טבלת הערכה → קלפים, לא overflow-x scroll** — קלפים נוחים לקרוא; scroll אופקי בטבלה הוא UX רע.
- **`data-label` ב-JS ולא ב-HTML הסטטי** — הטבלה נוצרת דינמית. הוספה ב-`renderEvaluation` היחיד שיש לזכור — לא צריך לסנכרן עם המבנה הסטטי.
- **Tooltip tap עם stickyEl, לא לזרוק את ה-hover** — desktop ממשיך לעבוד בלי שינוי בחוויה. Touch לא מקבל hover אז אנחנו לא דורסים.
- **`positionPopup` מודד אחרי visible** — מבטל הנחות שגויות על רוחב הפופאפ במובייל (CSS אחר → גודל אחר).
