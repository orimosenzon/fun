# Haskala — ידע כללי על הפרויקט

## מהות הפרויקט
מערכת אדמיניסטרציה אוטומטית של כיתת לימוד. תלמידים כותבים שיעורי בית על נייר בעט, מצלמים בטלפון, ומעלים ל-Google Classroom. המערכת מתמללת את כתב היד באמצעות Claude Vision, בודקת את התשובות, ומחזירה משוב — אוטומטית או דרך אישור של המורה.

## היסטוריה
- **גרסה ראשונה (≈2024):** התחלנו לעבוד על הרעיון לפני קצת פחות משנתיים. צוות: אורי מוסנזון, אבישי שלוש, ירון קדם.
- **מיקומים גיאוגרפיים של הצוות:** אבישי — תל אביב. אורי — פרדס חנה. ירון — שוודיה (לאישור).
- עבדנו כחודשיים ואז זנחנו. שתי סיבות עיקריות:
  1. *זמינות אישית* של חבר הצוות שהוביל (אורי).
  2. *מצב טכנולוגי:* המודלים של אז (תחילת 2024) היו חלשים יותר ב-vision של כתב יד עברי, ולא היה כלי קוד אגנטי כמו Claude Code שיקצר את הפיתוח.
- **2026: חזרה לפרויקט.** הסיבות לחזור עכשיו:
  - מודלים חזקים בהרבה (Claude Opus 4.7 Vision מטפל בכתב יד עברי ברמה שלא הייתה אפשרית ב-2024).
  - Claude Code כשותף פיתוח.
  - Google Classroom הבשיל — יותר API surface, חדירה משמעותית לשוק החינוך הישראלי.

## דרישות עסקיות
- **מצב היברידי**: מקרים ודאיים → משוב אוטומטי. מקרים מורכבים → סקירת מורה.
- **תחום לימוד**: כללי / מגוון (לא חסום למקצוע ספציפי).
- **שפה**: עברית.

## ארכיטקטורה
- **Backend**: Flask (תואם ל-letras, nudge, sidekick)
- **OCR + בדיקה**: Claude Vision API
- **אינטגרציה**: Google Classroom API + Google Drive API (OAuth 2.0)
- **פריסה מתוכננת**: Render (כמו פרויקטי Flask אחרים)

## למה Flask ולא Apps Script / Add-on
- תואם לסטאק קיים של המפתח.
- SDK של Anthropic ב-Python — תמיכה מלאה ב-Vision, caching, וכו'.
- לא דורש פרסום ב-Google Workspace Marketplace.
- חיסרון מקובל: לא מוטמע ב-Classroom UI עצמו; המורה ניגש לממשק web נפרד לסקירה.

## זרימה מתוכננת
1. תלמיד מצלם → מעלה ל-Classroom assignment.
2. שרת Haskala מסנכרן הגשות חדשות (polling / push notifications של Classroom).
3. כל תמונה → Claude Vision: תמלול + בדיקה + ציון בטחון.
4. ציון בטחון גבוה → משוב אוטומטי כ-comment ב-Classroom.
5. ציון בטחון נמוך → תור סקירה עבור המורה ב-web UI.

## מצב נוכחי (2026-05-14)
- **POC ראשון של OCR בנוי ועובד** — Flask app שמקבל PDF של תרגיל מצולם ומחזיר תמלול ורבטים מ-Claude Opus 4.7.
- **תצוגת alignment שורה-שורה**: ממיר PDF → PNG ב-200 DPI (pymupdf), מבקש מ-Claude JSON מבני עם `text + y_top + y_bottom`, חותך כל שורה כתמונה ומציג ליד התמלול. דרישה מקורית של אורי כדי להעריך איכות OCR ויזואלית.
- **prompt engineering ל-OCR**: שמירה מדויקת על שגיאות כתיב, פיסוק, אותיות גדולות/קטנות, ומבנה שורות. שורה לא קריאה → `[לא קריא]`.
- **תיקוני alignment**: padding של 30px סביב כל חיתוך + `normalize_line_heights` שמרחיב outlier-ים דקים מדי לחציון העמוד (Claude לפעמים מחזיר חיתוך של הקו המודפס במחברת במקום של כתב היד).
- *עדיין לא*: אינטגרציית Classroom API, OAuth flow, ממשק מורה, פריסה, מערכת בדיקה (רק תמלול).

## עלות מוערכת
- Opus 4.7: ~$0.02-$0.03 לעמוד תרגיל. כיתה של 30 תלמידים = $0.6-$1.2 לבדיקה.
- עם prompt caching (מופעל) — חיסכון של ~90% על system prompt לקריאות עוקבות באותו חלון 5 דקות.

## שאלות פתוחות / החלטות לעתיד
- האם למורה יש חשבון Google Workspace for Education? (משפיע על הרשאות Classroom API)
- מודל ברירת מחדל: opus-4-7 לאיכות, sonnet-4-6 לעלות נמוכה — להשוות איכות אחרי שיש לנו דוגמאות מספיקות.
- האם להחזיק היסטוריית הגשות במסד נתונים מקומי, או להסתמך אך ורק על Classroom כמקור אמת.
- אם alignment השורות עדיין לא מספיק טוב — מעבר ל-image processing מקומי (horizontal projection) במקום להסתמך על קואורדינטות מ-Claude.
