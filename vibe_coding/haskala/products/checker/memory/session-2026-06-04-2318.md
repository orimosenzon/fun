# סשן 2026-06-04 23:18 — מסך אישור כיוון לפני פענוח + הרחבת deskew

## מה נעשה

### 1. דיאגנוסטיקה לבעיית cropping בעמוד ערבית
המשתמש שיתף עמוד ערבית שבו התעתיק נראה "מוסט" ביחס לתמונות הסטריפים. הלוג הראה `heights min/med/max=80/91/240 near_empty_strips=none` — סגמנט יחיד פי 2.6 מהחציון.

**שורש הבעיה:** ב-`segment_into_lines`, `bounds[0]=0` ו-`bounds[-1]=len(region)-1` תמיד; כשאזור הכתיבה (`_writing_region`) מתרחב מעל ראש הכתיבה האמיתי, סגמנט 0 בולע את הריק העליון + השורה הראשונה. ויזואלית: התמונה נראית ריקה והתעתיק שלה (שורה 1) מתאים למה שנראה בתמונה 2.

**תוספת ללוג:** הוספה של `edge_seg first/last=X/Y` ב-`segment_into_lines` כדי לזהות מהר אם הסגמנט הראשון/אחרון חורג מהחציון.

### 2. דיאגנוסטיקה לבעיית סיבוב בעמוד עברית
עמוד שני (עברית) — סטריפים הראו קווי שורה אלכסוניים עבים. הלוג: `deskew=6.2°` — בדיוק על גבול ה-`max_angle=6.0`. כשהאופטימום נופל בגבול, האופטימום האמיתי כנראה מחוץ לטווח.

**תיקון:** ב-`deskew_page`:
- `max_angle` הורחב מ-6.0° ל-10.0°
- אזהרה בלוג כשהאופטימום נופל בטווח 0.5° מהגבול

### 3. תקלה חדשה: auto_rotate שגוי (180°)
עמוד שלישי הראה `auto_rotate: h_std=767.4 v_std=743.0 → picked 180°`. h_std ≈ v_std (אמביגואי) → רוטציה שגויה → OCR החזיר "[לא קריא]" לכל השורות.

**מסקנה:** הרחבת deskew לא תעזור כאן. דרושה התערבות אנושית.

### 4. פיצ'ר חדש: מסך אישור כיוון לפני פענוח
פלואו דו-שלבי במקום העלאה ישירה ל-`/decode/start`:

**Backend (app.py):**
- `POST /preview` חדש — מקבל קובץ (multipart/JSON path), מחזיר `{preview_id, pages: [{page, image_b64, suggested_fine_angle}]}`. כל עמוד עובר `auto_rotate` + מדידת `deskew` כדי לקבל ברירת מחדל לסליידר. ה-bytes נשמרים ב-`PREVIEWS` (TTL 30 דק').
- `_load_upload()` חדש — helper משותף ל-`/preview` ו-`/decode/start` ש-מנהל את אופציות ההעלאה (multipart, path בדסקטופ, preview_id ב-web).
- `/decode/start` הורחב לקבל `preview_id` + `rotations` (רשימת `{rotation_90, fine_angle}` לכל עמוד).
- `process_pdf_stream` הורחב — כשמועברים rotations, מדלגים על deskew_page האוטומטי ומיישמים את בחירת המשתמש (`auto_rotate` עדיין רץ ראשון כדי שה-baseline יתאים ל-preview).

**Frontend (templates/index.html):**
- אזור CSS חדש: `.preview-box`, `.preview-page`, `.preview-stage`, `.preview-controls`.
- HTML container `#preview-box` בין progress-box ל-error-banner.
- JS: `requestPreview()`, `showPreview()`, `buildPreviewPage()` — בונה כרטיס לכל עמוד עם תמונה, 3 כפתורי סיבוב (⟲90°, ⟳90°, 180°), סליידר ±15° עם תצוגת ערך חי, וכפתור איפוס. סיבוב חי דרך `transform: rotate()` + החלפת max-width/max-height כשהסיבוב 90°/270°.
- כפתורי "פענח" / "ביטול" בתחתית.
- ה-handlers של `decode-btn` ו-`fallback-pdf` שונו לקרוא ל-`requestPreview` במקום `startDecode` ישיר.

## הערות ארכיטקטוניות
- `PREVIEWS` cache הוא in-memory בלבד (כמו `JOBS`) — נמחק ברסטרט של Flask. ל-deploy על HF זה בסדר כי כל user session קצר.
- כשהמשתמש לא נוגע בסליידר/כפתורים, ה-fine_angle בברירת המחדל הוא הערך שהאלגוריתם המליץ — אז רוב המקרים מקבלים את אותה התנהגות כמו לפני (אבל עם הזדמנות לתקן 180° שגוי בקליק אחד).
- כש-rotations מועברים, `auto_rotate` עדיין רץ. הבחירה הזו מבטיחה שה-preview שהמשתמש ראה זהה לתמונה שעוברת ל-OCR. הסיכון: אם auto_rotate מחזיר משהו שונה בקריאה השנייה — אבל הוא דטרמיניסטי על אותו קלט.
