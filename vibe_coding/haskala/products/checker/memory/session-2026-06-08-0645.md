# סשן 2026-06-08 06:45 — האצת הכנת התצוגה המקדימה

## מטרה
אבישי דיווח שלפעמים הכנת התצוגה המקדימה (מסך אישור הסיבוב שלפני ה-OCR) לוקחת הרבה זמן.

## אבחון
צוואר הבקבוק ב-`run_preview_job`: כל עמוד עובר `auto_rotate` ואז `deskew_page` **בגודל מלא**.
- `deskew_page` ([app.py](../app.py) ~657) מבצע ~52 סיבובים לעמוד (41 גס ב-0.5° + 11 עדין ב-0.1°),
  כל אחד עם `_smoothed_profile`. עלות O(פיקסלים).
- `file_to_page_images` **לא מקטין צילומים** (רק PDF עובר רינדור), אז צילום טלפון ~10MP נכנס בגודל מלא — שם ההאטה הכי קשה.

## הפתרון (יושם, נבדק, נפרס)
התובנה: `auto_rotate`/`deskew_page` מחשבים רק **זווית** — נתון גאומטרי **בלתי-תלוי רזולוציה**.
והתצוגה מוצגת ב-frontend ב-`max-height:60vh` בלי zoom. אז עובדים על העתק מוקטן.
- קבוע חדש `PREVIEW_WORK_EDGE = 1200` + helper `_downscale_to_edge(img, max_edge)` (LANCZOS, no-op אם קטן). ליד `original_preview_b64`.
- `run_preview_job`: `work = _downscale_to_edge(img, PREVIEW_WORK_EDGE)` לפני `auto_rotate(work)`+`deskew_page`, ושורת timing ל-`haskala.log` (`preview page N: WxH -> work WxH, prep Xs`).
- **ה-decode/OCR לא נגעתי בו** — `PREVIEWS` שומר בייטים גולמיים, `process_pdf_stream` מרנדר מחדש ב-`RENDER_DPI=200`. איכות OCR לא השתנתה כלל.
