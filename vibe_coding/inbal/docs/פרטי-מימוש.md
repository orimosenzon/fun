## מודל הנתונים (Prisma Schema)

```
User
  ├── role: ADMIN | STUDENT
  ├── password (nullable - OAuth users don't have one)
  └── accounts[] → Account (Google/Facebook)

Group
  ├── dayOfWeek: 0-6 (ראשון-שבת)
  ├── time: "10:00"
  ├── duration: minutes
  └── isActive: boolean

GroupEnrollment (User ↔ Group)
  └── status: ACTIVE | PAUSED | DROPPED

Session (מופע שיעור ספציפי)
  ├── groupId
  ├── date: DateTime
  └── status: SCHEDULED | CANCELLED | COMPLETED

SessionRegistration (User ↔ Session)
  ├── status: REGISTERED | CANCELLED | TRANSFERRED | ABSENT
  ├── transferredFromId (אם הגיע מקבוצה אחרת)
  └── transferredToId (אם הועבר לקבוצה אחרת)

Payment
  ├── amount: Float
  ├── type: MONTHLY | SESSION | OTHER
  └── date: DateTime
```

## לוגיקות עסקיות מרכזיות

### יצירת שיעורים אוטומטית
`POST /api/groups/[id]/sessions`
- מחשב את התאריך הבא לפי `dayOfWeek` ו-`time` של הקבוצה
- יוצר N שיעורים (ברירת מחדל: 8 שבועות קדימה)
- לכל שיעור - רושם אוטומטית את כל התלמידים הפעילים (`ACTIVE`) בקבוצה
- מדלג על שבועות שכבר קיים בהם שיעור

### הרשמה לקבוצה
`POST /api/enrollments`
- יוצר `GroupEnrollment`
- מוסיף `SessionRegistration` לכל השיעורים העתידיים של הקבוצה

### ביטול חד-פעמי
`PATCH /api/registrations/[id]`
- משנה סטטוס ב-`SessionRegistration` בלבד
- לא נוגע ב-`GroupEnrollment` (התלמיד עדיין רשום לקבוצה)

## אימות (Authentication)

### Providers
1. **Credentials** - בדיקת אימייל + bcrypt hash של סיסמה
2. **Google** - OAuth2 דרך NextAuth
3. **Facebook** - OAuth2 דרך NextAuth

### Role במשתמש
- תפקיד נשמר בטבלת `User.role`
- עובר ל-JWT token דרך callback `jwt`
- זמין ב-session דרך callback `session`
- בדיקה בכל API route: `(session.user as { role: string }).role !== "ADMIN"`

### PrismaAdapter
- מנהל אוטומטית את טבלת `Account` לחשבונות OAuth
- משתמש ב-JWT strategy (לא session בבסיס הנתונים)
