## סטאק
HTML + CSS + JavaScript מודולרי (ES modules). **אין build, אין תלויות, אין CDN.**
Canvas 2D להרכבת התמונה, WebAudio למיקס, MediaRecorder לייצוא, IndexedDB לשמירה.

## החלטות עיצוב שכדאי לזכור
- **מודל המעבר:** `clip.tin = {type, dur}` יושב בראש הקליפ הנכנס ודורש קליפ צמוד
  לפניו. בזמן המעבר הקליפ היוצא ממשיך לשאוב פריימים מהמקור *אחרי* נקודת היציאה
  שלו (ואם נגמר, פריים קפוא). זה נותן מעבר אמיתי בלי לשנות את אורכי הקליפים.
  בגלל זה יש דגל `tail` ב-`drawClip` וב-`clipGain`: בזנב מדלגים על הדעיכות של
  הקליפ, אחרת הן היו מאפסות אותו בדיוק בזמן המעבר.
- **סנכרון ניגון:** שעון אחד (`performance.now`) מוביל, וכל `<video>` מתוקן אליו.
  סטייה > 0.22 שנ׳ = seek; סטייה > 0.02 = תיקון עדין ב-`playbackRate`.
- **דריסה (overwrite):** הנחת קליפ חותכת את מה שמתחתיו (`carve`), כמו ב-NLE רגיל.
- **היסטוריה:** צילום JSON של כל הפרויקט לפני כל שינוי (`beginChange`/`commit`).
  הבלובים לא נכנסים לצילום, הם יושבים ב-registry נפרד ב-media.js לפי mediaId.
- **האינספקטור לא נבנה מחדש בזמן גרירת מחוון** (דגל `interacting`), אחרת הגרירה
  הייתה מתנתקת באמצע.

## ייצוא: תמיכת קודקים
`MediaRecorder.isTypeSupported` שונה בין מערכות. בלינוקס (Chrome 138) **אין AAC**,
ולכן `video/mp4;codecs=avc1.42E01E,mp4a.40.2` לא נתמך והנפילה היא ל-
`video/mp4;codecs=avc1.42E01E,opus` (H.264 עם Opus בתוך MP4). ב-Windows/Mac
האפשרות הראשונה כן זמינה. **חשוב:** `video/mp4` הגנרי מייצר VP9 בתוך MP4, שזה
קונטיינר חוקי אבל נגנים רבים לא פותחים. לכן רשימת המועמדים ב-`export.js`
מסודרת לפי תאימות אמיתית ולא לפי סדר אקראי.

## איך בודקים
Playwright + Chrome אמיתי (`channel="chrome"`, לא chromium, כי צריך H.264),
עם קובצי בדיקה מ-ffmpeg. הסקריפטים שנכתבו בסשן הראשון:
`test_edit.py` (ייבוא/חיתוך/ripple/מעבר/ניגון/undo), `test_ui.py` (לוחץ על כל
כפתור וקיצור ומחפש שגיאות ריצה), `test_e2e.py` (עריכה מלאה + ייצוא + בדיקת
הפריימים המיוצאים ב-ffmpeg), `test_trans.py` (מונטאז' של כל 12 המעברים).
`window.__vedit = {state, engine, proj, rt}` נחשף בכוונה כדי לאפשר בדיקות.
