# factotum — ידע כללי על הפרויקט

## מהו factotum
פרויקט-תשתית (meta) שבו Claude מבצע עבודות הקמה/קונפיגורציה של שרתים, עבודת ענן
(בעיקר Azure) ופעולות קונסולה **בשם המשתמש**, במקום התהליך המסורבל של
"צילום מסך → הסבר → המשתמש לוחץ". כל פעולה מתועדת כאן.

> **פקטוטום** (factotum): לטינית *fac totum* = "עשה את הכל". משרת רב-תכליתי
> שמבצע כל סוג עבודה. השם משקף את התפקיד: לבצע את כל עבודת התשתית בשם המשתמש.

## הצורך (מה הוליד את הפרויקט)
המשתמש (אורי) צריך לעיתים קרובות להקים שרת רשת ולקנפג אותו, או להרים מודל
ב-Azure. כיום זה עובר דרך פינג-פונג של צילומי מסך כי Claude לא יושב על המכונה/
הקונסולה שבה הפעולה קורה. **הבעיה היא גישה, לא "computer use".** רוב המשימות
האלה ניתנות לביצוע מ-CLI.

## הארכיטקטורה — שלוש שכבות (לפי כמה הצורך ויזואלי)
1. **גישת CLI ישירה (ה-80/20):**
   - שרתים מרוחקים → SSH; Claude מריץ פקודות ישירות דרך bash.
   - Azure → `az` CLI מכסה ~90% מהפורטל (resources, פריסת מודלים, quota, endpoints).
   - הכי אמין/מהיר/זול; נותן לוג טקסט מלא כסיכום אוטומטי.
2. **אוטומציית דפדפן (Playwright):** ל-~10% שאין להם CLI. מדבר עם ה-DOM, לא פיקסלים.
   מצלם מסך בכל צעד → "סיכום עם תמונות" בחינם. (ראֵה sidekick — אותו רעיון ב-Selenium.)
3. **computer use אמיתי (קונטיינר דמו):** כרגע לא נדרש. רק למשימה ויזואלית פתוחה
   באתר לא צפוי. overkill לעבודת שרתים/Azure.

## כללי אישור ובטיחות (קריטי)
המשתמש נגנב בעבר דרך מפתח API. Claude פועל לבד על פעולות לא-הרסניות, **ועוצר
לאישור מפורש על:**
- כל פעולה שעולה כסף בענן (יצירת VM/GPU, פריסת מודל בתשלום) — כולל הסבר עלות
  צפויה + הגנות (budget cap, IP restriction) **לפני**, לא אחרי.
- מחיקות (קבצים/resources/branches), push, שינוי CI/CD.
- כל דבר שחושף/מעביר סוד.

## מבנה תיקיות
- `memory/` — project-knowledge + סיכומי סשנים (session-YYYY-MM-DD-HHMM.md)
- `logs/`   — לוגי טקסט של ריצות CLI
- `screenshots/` — צילומי מסך מ-Playwright לתיעוד

## סטאק

- Azure CLI (`az`)
- Playwright (Python) לאוטומציית דפדפן + צילומי מסך (שכבה 2)
